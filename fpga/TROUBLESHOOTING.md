### 离群值的"整齐码"反推（09-10，关键推理）
```
2Vpp 时信号码域 ≈ 277~747（vpp≈470，居中 512）
  vpp=239  → 若 min 仍 277，则 max≈516 ≈ 512（中码）；若 max 仍 747，则 min≈508 ≈ 512
  vpp=744  → 若 min 仍 277，则 max≈1021 ≈ 1023（全 1）
  ⇒ 坏值像是"某个采样点读到 0 / 512 / 1023"这类整齐值
```
**→ 高度像"采样点恰好落在 ADC 输出数据翻转沿"**：10 位同时在变，采到的是各位随机混合值
（0/512/1023 = 全 0 / MSB 独高 / 全 1，都是混合的典型结果）
- ⇒ 指向 **采样相位/建立裕量**，而非位线接触不良
- 但 270° 已是理论最优（裕量 10ns）却仍偶发 → 怀疑 **实际 tOD 与 25ns 有偏差**
  （若 tOD 接近 20ns/40ns 整数倍 → 数据翻转贴近时钟沿 → 270° 裕量大幅缩水）
- 待验证：诊断上报 `cur_max`/`cur_min` 原始码 → 一次性看清坏值形态

### 28 号：**诊断上报首测 —— 根因定位到 bit5（ADC_D5 飞线）**（09-10 12:14，决定性）
上报格式 `<max码>,<period>,<bin>,<min码>`，源 = 100kHz/1Vpp，30 行：

| 字段 | 观测 | 判读 |
|---|---|---|
| **max 码** | **621~623 极稳**；一次跳 **880** | max 基本干净（880 为另一类多位事件） |
| **min 码** | **分两簇**：低簇 **136~142** / 高簇 **168~185** | ⚠️ **两簇相差 ≈ 32** |
| period / bin | 500 / 3 稳 | 主链路正常 |

**核心发现：`1 6 8 − 1 3 6 = 32`，正好是 bit5 的权重！**
```
136 = 0b0010001000   (bit7 + bit3)
168 = 0b0010101000   (bit7 + bit5 + bit3)   ← 差的就是 bit5
```
**→ bit5（= 32）在翻转。而 bit5 = `ad_data[5]` = ADC_D5 = 那根手工飞线到 P17！** ✓✓✓

**交叉验证（回头看旧数据，完全吻合）**：
- 早前 100kHz 的 vpp 序列在 **447~455 / 478~485** 两簇间跳 → **Δ ≈ 32** ✓
- 当时误判为"偶发单点毛刺"，实为 **bit5 持续翻转**（vpp = max−min，min 掉 32 → vpp 涨 32）
- 也解释了为什么"小信号更容易看到"：幅度小时 32 LSB 占比更大

**根因链（v2）**：
```
现象：vpp 在 ±32 的两簇间跳 / VOFA 折线图大量上下尖刺
  ↓ 直接原因：窗口 min 偶尔低 32 → vpp 涨 32
  ↓ 根本原因：ad_data[5]（=ADC_D5，P17 手工飞线）信号完整性差、边沿迟滞
             → ADC 输出翻转时该位来不及建立，采样采到旧值
  ↓ 为什么是 bit5：只有 bit5 走飞线（R19=CPU 专用脚不可用，改飞 P17）
  ↓ 如何避免：飞线重焊/缩短/串 33Ω 源端电阻/伴地线；理想是换用有正规走线的空闲 IO
```

### 42 号：★★ 【已作废·我推理错了】"接地制造假毛刺"的说法 —— 数值差在中码处**就是 1**

**我当时的错误推理**：
> "0V 接地 → 码在 511↔512 抖动 → 10 位里 9 位同时翻转 → 数值跳 511 LSB → 假毛刺"

**错在哪**：**把"翻转的位数"当成了"数值差"**。
`511 = 0b0111111111` → `512 = 0b1000000000`，**数值差 = |512−511| = 1**，
而 `glitch_count` 用 `diff_raw = |a−b|`（**数值差**），所以它**只会记 1，根本不会触发 THR=16**。
⇒ **"接地会制造假毛刺"不成立，此条作废。**
**教训（已入共性问题集思路）：讨论"跳变"时必须明确是"位翻转数"还是"数值差"——两者在中码处相差 511 倍。**

**但现象本身仍然要解释**（这才是真问题）：

- 判断"静态 vs 乱跳"唯一可信法：**DC 耦合 + 慢时基 + 就近短地线**；或用 **DAC_OUT（屏蔽同轴）** 看 FPGA 侧 ADC 数据。
- 💡 **线缆限制的解法**：发生器(BNC)→BNC转鳄鱼夹→夹 ADC_IN SMA；示波器→唯一那根 SMA-BNC→DAC_OUT。
  **更省事：低频测试根本不用示波器——top_system 一直通过 UART 报 vpp/period，直接看 VOFA 即可。**

### 关键提醒（测量方法，09-10）
- ⚠️ **AC 耦合 + 长鳄鱼夹** 在 50MHz 时钟旁 → 任何引线都显示"密集噪带"，是典型假象，不能据此判数据线坏。
- 判静态/乱跳必须：**DC 耦合 + 慢时基（10ms/div）+ 就近短地线**。
- 先做 control：探头 tip 夹到自己地夹 → 仍噪=引线拾取（假象）；变平=测法有效。

### 最终原因（根因链）
```
现象：FFT bin 乱跳 + mag 恒 5万
  ↓ 直接原因：fft64 输出频谱全是假峰（mag 饱和量级、bin 无意义）
  ↓ 根本原因：行为级 RTL（双端口 RAM 数组读写 + initial 初始化 twiddle ROM + 32bit 蝶形乘法）
             综合成 FPGA 硬件后行为与 iverilog 仿真严重不一致（RAM 推断/ROM 初始化/乘法优化差异）
  ↓ 为什么会出现：仿真只验证"行为"不验证"综合结果"；行为级 RTL 隐含对硬件的假设（同步 RAM、ROM 内容）未被综合器兑现
  ↓ 如何避免：复杂算法（FFT/FIR/CORDIC）优先用厂商 IP；隔离测试把"被测模块"从"外部链路"剥出来再上板
```
衍生问题根因链（vpp 毛刺）：
```

  ↓ 直接原因：1024 窗口 max-min 对"单点/少点毛刺"极敏感——只要窗内有 1 个异常值抬高 max 或压低 min，vpp 就跳
  ↓ 根本原因：ad_data 数据流整体不可信（并非"偶发单点毛刺"，而是接近满量程乱跳）
             ★ 已排除：不是 PLL 失锁（mag bit17 无 13 万级）
             ★ 已排除：不是 CDC 亚稳（去 PLL 域反而更糟；加同步器既不根治也不加重）
             ★ 已排除：不是 vpp_measure 算法（代码复查正确；且 period/bin 同源数据稳=数据大体干净）
             ★ **已排除（09-10）：不是输入路径（信号源/线缆/ADA107 调理）——ADC_IN 接地后 vpp 仍大幅摆动**
             ★ **已排除（09-10）：不是 FPGA→DAC 通路——内部 DDS 正弦输出完美（W1+F0500000）**
             ★ **锁定（09-10）：故障域 = ADC→FPGA 段**（接地时 ADC 应恒 512，实测 adc10_sync 大幅乱跳）
             ★ 段内待分层（09-10 下一步）：ADC 时钟（50MHz 是否到 ADC）/ ADC 数据线（应为稳定直流）/ ADC 供电与基准
  ↓ 为何历史反复误判：换 FFT IP 前 bin/mag 全乱掩盖了 vpp 问题（时间相关≠因果）；
             FFT 修好后 vpp 毛刺才暴露 → 被误当成"新引入问题"
  ↓ 如何避免：加"修复"前先量化原现象+长窗口 A/B（短窗口 5 行数据误判过 2 次）；
             隔离输入（ADC_IN 接地）是区分输入路径 vs 板内的最低成本实验
```

### 尝试过的方法（失败明细）
1. PLL 相移 180°→270°：**有效果但没根治**（mag 跳变小）。为什么当时怀疑：3PA1030 tOD=25ns vs 20ns 周期，同相采裕量确实小——但这是"另一个真实存在的小问题"，不是本案主因。**教训：多个问题叠加时，别把"真问题 A 的小改善"误当成"主问题 B 的进展"。**
2. 怀疑信号源：换频率测试。为什么失败：signal chain 里 vpp/period 都正常，只有 FFT 异常 → 问题在 FFT 上游内部而非输入。
3. 在 fft64 外反复调参（MAG_THRESHOLD 等）：掩盖而非解决。
4. 去 PLL 域实验（clk50 同域直采，23:00）：**失败且反向证明 PLL 域必要**。当时假设"PLL 采样域引入毛刺"→ vpp 双模态更糟。教训：PLL 180° 让采样点避开 3PA1030 数据翻转沿（tOD=25ns vs 20ns 周期），是 vpp 稳定的必要时序设计；T01 原"PLL 相位已排除"仅适用于 bin 乱跳。
5. 同步器复测（23:30）：解开 2 拍同步器 + 下游 4 处改 sync → vpp 401~453（偶发 744~745），**无密集塌陷**。教训：首次"同步器加重"判定基于短窗口误判，同步器应视为**无害安全网**而非根因或元凶。

### 最终解决方法
1. `fft64.v` 弃用（上板不可用，仅保留作仿真参考）；新增 `src/fft_wrapper.v` 包高云 FFT IP：
   - IP 配置：64 点 Fixed/Forward/Natural/**RS111**（每级>>1 = /64，与自写缩放一致）/16bit/DSP/EBR
   - 握手协议（官方 testfft_top 示例）：start 单脉冲 → **ipd=1 期间每拍喂 1 点** → eod 输入完 → busy 计算 → opd=1 输出 idx 0~63
   - 采集适配：din_valid 稀疏采 64 点入 RAM → burst 喂 IP → 输出转发（fft_peak 零改动）
   - rst 高有效（顶层 sys_rst_n 反相）
2. PLL 采样域保留（PLL_ADV clkout0 0°→ADC 时钟 / clkout1 180°→采样域）——**vpp 稳定的必要时序**，勿再移除。
3. clk50 域 2 拍同步器保留（adc10_sync/adc_valid_sync，下游 vpp/freq/fft/直通全用）——无害安全网。

### 经验总结（沉淀到逻辑集）
- L27：行为级 FFT 仿真全对、上板错乱 → 换厂商 IP 核；隔离测试 = 最快的根因定位器

1. **现象异常先分层**：信号源？ADC 接口？时钟域？算法？——用隔离测试剥开（内部信号源替代外部输入）
2. **FFT/复杂算法直接评估厂商 IP**，不自写行为级 RTL（或自写前想清楚综合差异）

#### 发现 A：样本**成对重复** → 采集时钟其实是 **25MHz**

1. **偏差幅度 ∝ 同翻位数**：10 位 → ~±340；8 位 → ±340/+67；4~6 位 → ±20；2~3 位 → ±10~16
2. **坏值是"逐位混合"的整齐值**：`170 = 0b00_10101010` 相对 `511=0b01_11111111 → 512=0b10_00000000`，

3. **MSB 最后稳定**：中码**上升**穿越 → 坏值偏低（138/170/172）；**下降**穿越（645）→ 坏值偏高（577）—— **方向对称，同一机制**

```

⇒ 多位同翻时输出建立时间 >5ns（10 路输出同时冲电容 + 共地弹跳）
⇒ **采样点落在跳变过程里 → 锁存新旧混合码**   ★ 这就是"vpp 毛刺"的全部
```

**建立裕量 5ns → 30ns（6 倍）**。改动仅一个 IP 参数，不动 RTL、不动频率标定。

**⚠️ 此前"270° 是最优采样点、有 10ns 裕量"的推导（基于 50MHz）已作废。**

#### 一次解释了所有旧疑团

| 旧现象 | 新解释 |

### 52 号：⚠️ IP 重新生成会冲掉手工改动（09-10 18:25 实证）

- 验证：修后跑 `gw_sh` 全量构建 → **零 error** ✓。
- **通用规律**：**凡"手工改过 IP 生成文件"的地方，重生成后必须逐条核对**。
  更稳的做法：**不要手改生成文件**，需要的信号尽量在 RTL 侧自己产生。

### 55 号：★★★ 抗噪 vpp 估计（峰值带均值法）—— 写它时踩的 3 个 RTL 坑 + 1 个 TB 坑（09-10 23:xx，[已确认][已修复]）

**背景**：上板实测 `max−min` 比示波器基准系统性高 +5 LSB（2Vpp 时 +5.08%，题2 容差 ±5% 只剩 3mV），

**写实现时踩的坑（都是靠仿真抓到的，值得记）**：
1. **多驱动竞态**：我把 `dv_run`（除法器起跑标志）在**两个 always 块**里都赋值
   （FSM 里置 1、除法器里清 0）→ 非法多驱动 → 仿真里 NCAA 后写者胜 → **偶发 vpp=0**。
   ⇒ 修法：一个信号只在一个 always 块里赋值；跨模块用 `req/ack` 握手（FSM 只给 `dv_req`，除法器自己管 `dv_run`）。
2. **"完成拍"重启同一操作**：除法器 `if (!dv_run && dv_req)` 装载起跑，
   但**完成那一拍 `dv_run` 已归 0 而 `dv_req` 还没清** → 同一次除法被重启一遍 →
   第二次除法拿到第一次的商 → `mean_lo == mean_hi` → **vpp ≈ 1（不是 0，更容易骗过人）**。
   ⇒ 修法：装载条件加 `&& !dv_done`。
3. **带宽太窄 → 带内样本数会掉到 0**：带宽 3 LSB 时，两遍窗口的**相位对齐**一变，
   第二遍可能一个样本都不落在峰值带里 → 商 = 0 → vpp 偶发 0/1。
   ⇒ 修法：带宽 = `max(pp>>N, BAND_MIN=4)`（自适应 + 绝对下限），并对 `cnt < 4` 回退 `max−min`。

- TB 喂完 N 拍就停喂 → **最后一个窗口数据冻结 → `max==min` → 读数 0**，

- ⇒ **规矩：被测窗口必须"持续喂数据"，统计量要在喂数据期间累加**；停喂后的窗口一律不算。

### 56 号：★★★ 低频段时域显示不达标 → 抽取回传（`S` 命令 / `#DEC` 行）+ 整机端到端联仿（09-11，[已确认][已修复][仿真验证]）

**现象（板上频率扫描，09-10）**：题2 要求"时域界面至少显示 2 个完整周期"，但上行的一帧原始数据
固定是 **1024 拍 = 20.48µs**：100kHz 只有 2.05 个周期，20kHz 只有 0.41 个，1kHz 只有 **2%** ——
上位机上看到的是一条近乎水平的斜线。**不是采样率不够，是"窗口长度"不够。**

**为什么不能靠"降采样率"解决**：ADC 采样时钟（25MHz）与缓冲写时钟（50MHz）由板上 PLL 决定，
而 135° 采样相位正是坏值问题的修复成果（T53）——**动它就是回退已验证的修复**。
⇒ 唯一安全的自由度是"**存储时抽掉一些拍**"。见 L49 / L50。

**做法**（`ADDA/src/raw_dump.v`）：
- 新增按实测周期自适应的抽取比 `D = max(2, (period_avg>>7) & ~1)`（上限 4096）
  → 一帧覆盖 `1024·D` 拍，帧内周期数恒 ≈8；>50kHz 段 D 触底为 2，仍有 4.1 个周期（全段最小值）
- **D 必须取偶数**：每源样本占 **2** 个缓冲点，取偶才能保证"每 D 拍取的那一点"落在同一相位
  → 严格等价于对 25MSPS 源序列做 `D/2` 抽取，不会把两份副本混进一帧
- 新增命令 `S`（抽取）与帧头 `#DEC nnnn`（本帧的 D）；**`R` 保持全速 D=1 逐字节不变**
  → 诊断单点坏点必须继续用 `R`：抽取会跳过单点，**把要查的东西自己滤掉**
- `#DEC` 上报的是**本帧内容实际使用**的 D（在冻结点锁存）→ 帧内容与刻度永远自洽，
  代价是"换模式后第一帧仍是旧刻度"（TB 里专门断言了这条"滞后一帧"，防止后人顺手"修掉"）

**自造回归（本轮最值钱的一段）**：为了装下 13 位抽取比，把 double-dabble 的 BCD 寄存器
从 10 位加宽到 14 位，**一次踩了两条铁律**：
1. 为了"对齐 MSB"把值左移 → 等于把值 ×2 → **`#DEC` 报成真值的 2 倍**（1→2、4→8、4096→8192）；
2. 移位次数按"有效位宽"给 10 次而不是按寄存器位宽给 14 次 → 样本只移进去一部分 →
   **帧内数字整体错乱**（全 0 或乱跳）。
- 两条**都是老 TB（`sim/tb_raw_dump.v`）当场抓出来的**：它判"帧内必须严格 +1 递增"，
  是**与实现无关的数学性质**，所以"加宽寄存器"这种看起来无关的改动也躲不过。→ L49 / L43
- 另有一处**新 TB 自造故障**：阶段 5 期望 `#DEC=4096`，我以为"改完 `period_avg` 再触发"就生效，
  实测仍是旧 D —— 因为抽取比**只在冻结点切换**，要"再等一次填充 + 再触发一次"。
  这是我没想清"参数何时生效"，不是 RTL 错（与 L48 同型：**先分清"激励/时序没到"和"逻辑算错"**）。

**验证（不能上板之后，这就是全部证据；分四层，强度递减）**

| 层 | 用例 | 判据 | 结果 |
|---|---|---|---|
| ① 模块级 | `sim/tb_raw_dump_dec.v` | 喂 0..15 循环斜坡 → 帧内相邻样本差 ≡ D (mod 16)（与实现无关）；5 阶段：R/S 切换、滞后一帧、D=4 生效、clamp 4096 | ✅ 5/5 |
| ② 回归 | `sim/tb_raw_dump.v` | R 模式旧行为：帧内严格 +1、`#DEC=1`、`#DEC` 行不被算成样本 | ✅ |
| ③ **整机端到端** | `sim/tb_cmd_dump.v` | 真实 500kbps 时序打进 `top_system` → 解码上行 **5140 字节整帧**（`#RAW`+`#DEC`+1024 行+`#END`）；S/S/R/R → D=1/4/4/1；**帧内过中点次数/2 = 周期数 2/8/8/2** | ✅ 4/4 |
| ④ 上位机离线回放 | `tools/live_scope.py --selftest` | 5 档典型帧（D=1/2/18/390/3906）走**真实文本格式** → 解析 → 分析 → 判据（D、帧长、频率偏差、周期数） | ✅ 5/5 |

**关键收获**：③ 是"整机联仿"——用行为桩顶掉厂家 PLL/FFT 原语（见 U32），
就能在**没有板子**的情况下验证"串口命令 → 帧文本 → 上位机"整条链，包括 `#DEC` 这种
"只在两个设备之间约定"的东西。代价是慢（450 秒）→ 运行器分快/慢两档（默认只跑快的）。
