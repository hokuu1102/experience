| L40 | 测量/方法 | **聚合量（vpp/glitch 这类两个数字）定不了的案，去抓原始序列** | 09-10：vpp/glitch 折腾一整天未定案；1024 点原始波形 30 秒看清"坏点只在中码、逐位混合、MSB 最后稳定"。**先问"我需要的证据形态是什么"再动手排查** |
| L44 | 时序/相位 | **不要用"标称参数 + 零延时"推最优采样相位** → 用"差/差/好"三点反推真实环路延时 | 设跳变时刻 D(mod T)、采样相位 ψ，裕量=**圆上距离**(ψ,D)：0°差、270°差、135°干净 ⇒ 唯一解 **D≈35ns**（datasheet 只给 25ns）。据此 135°=20ns 裕量=**最优**，45° 只有 10ns。**纸面眼中心（假设 D=0）会指错方向**；一次相位扫描的本质就是测 D |

| L46 | 接口/判据 | **阈值型判据必须留"死区"（迟滞）**，否则噪声会造出假边沿 | 09-10 54 号：`(上一拍<512)&&(本拍>=512)` 无迟滞 → 下降穿越时噪声把某拍推回 ≥512，多算上穿 → 频率偶发 +6.8%/+14.4%。定量：N 个假边沿 ⇒ `avg=(16−N)·P/16`（N=1→468、N=2→437，与实测完全吻合）。修法：双门限 + 状态寄存器，H 按最小可用幅度反推（H=4 ⇒ 幅度需 >8 LSB）|
| L47 | 测量/统计 | **单点极值有系统性偏置**：`max−min` 会被噪声削峰抬高 ≈ 6σ（绝对量），要改成**峰值带均值** | 09-10 55 号：上板 max−min 高 +5 LSB（2Vpp 时 +5.08%，压容差），且幅度越小相对误差越大。两遍窗口：第1遍定 max/min → 带宽 `max(pp>>6, 4)`；第2遍累加峰值/谷值带内 sum/cnt → `vpp = mean_hi − mean_lo + 2·BAND/3`（+δ/3 是"带内均值低于峰值"的解析修正：正弦 −δ/3、三角 −δ/2、方波 0）。仿真：误差从 +3~+5 LSB 降到 0~±1 LSB |
| L48 | 验证/仿真 | **测窗口的 TB 必须"持续喂数据"** | 09-10 55 号：喂完 N 拍就停喂 → 最后一个窗口数据冻结 → `max==min` → 读数 0，差点误判成 RTL 故障（探针看到 `cur_max==cur_min` 才看穿）。统计量要在**喂数据期间**累加，停喂后的窗口一律作废 |
| L35 | 测量/ADC | **跳变幅度的"整齐程度"能区分"位翻转型"与"模拟噪声型"故障** | 跳变幅落在 2 的整数幂（32/64/128…）= 某条数据线在采样瞬间未稳定（位偏斜/建立裕量）→ 查时序与引脚；跳变幅连续分布 = 模拟噪声/SSN → 查电源与地 |

## 零、调试方法论（通用心法）

这一节是后面所有案例的公共部分，遇到新问题时按这个顺序走。

### 0.1 先分清问题属于哪一类

| 类别 | 特征 | 验证手段 |
|---|---|---|
| **环境问题** | 换个工具/版本就好了；软件报路径/模块缺失 | 换工具复现 |
| **仿真模型问题** | RTL 逻辑自洽，但接上某个模型就错 | 写最小 tb 单测该模型 |
| **设计问题** | 逻辑本身有时序/功能缺陷 | 波形逐拍推演 |
| **"假 bug"** | 现象看起来不对，其实是对的 | 算周期/算时序裕量 |

**这次踩的坑**：一开始把 L04（模型 bug）当成设计 bug 查，绕了很久。**判断依据**：真器件能工作而仿真不行 → 优先怀疑模型与器件行为不一致，逐条对照 datasheet。

### 0.2 分层定位法

```
现象 → 缩小范围 → 定位到信号 → 推演时序 → 确认根因 → 修复 → 数据验证
  ↑                                                        ↓
  └────────────── 不一致则回到上一层重新假设 ←──────────────┘
```

### 0.3 三个高性价比手法

**① 最小复现法**
把可疑模块单独拎出来写个 30 行 tb，用最简单激励验证行为。
> 实例：验证 HC595 移位方向，依次移入 `1, 0, 1`，观察 `diff` 是 `0x00→0x01→0x02→0x05`（左移）还是 `0x00→0x01→0x00→0x01`（右移）。一次就确认了方向，比在大工程里翻波形快十倍。

**② 反证法（改一个变量看现象是否消失）**
> 实例：怀疑 `TURN_FREQ` 是撕裂元凶 → 改回默认值 → 错值率从 9.6% 降到 1.6% → 确认。

**③ 值域验证法（最省时间的一招）**
不要逐拍看波形，**先看输出是否落在"合法值集合"里**。
> 实例：`q_seg` 应该永远是段码表里的 16 个值之一。修复前取值为 `0x58 0xD8 0xDC 0xFC 0xC1 0xC7`——**没有一个在段码表里**，一眼就知道错了，都不用细看时序。
>
> 同理：`q_sel` 应该永远是 4 个一热码 `0x01/0x02/0x04/0x08` 之一。

### 0.4 修复后必须做数据对比

"看起来对了"不算数。要有**修复前后的量化对比**：

```
修复前 q_seg: 0x58 0xD8 0xDC 0xFC 0xC1 0xC7   ← 全非法
修复后 q_seg: 0xB0 0xA4 0x92 0x99 0x83 0x88 0xA1 0xC6  ← 全合法段码
```

这种对比一眼就能确认修复有效，比任何描述都有说服力。

### 0.5 警惕"工具给你的读数"

分析脚本本身可能有 bug，会让你得出错误结论。
> 惨痛教训：第一版 VCD 解析脚本用 `val[0]` 补位宽，把 `b1`（2bit 的 `01`）补成了 `11`，导致把 `q_sel` 读成 `0xFF/0xFE`、把 `q_seg` 读成 `0xD8`。**花了很久在错误的读数上找规律。**
>
> **教训**：分析结论反直觉时，先怀疑脚本，用第二种方法交叉验证（比如直接 grep VCD 原文看记录格式）。

## 一、时序类

### L01. `sel_cnt` 领先 `sel` 一个时钟周期（**不是 bug**）

**现象**
波形上 `sel_cnt` 变化后，`sel` 要过一拍才跟着变。

**定位过程**
1. 看到两个信号差一拍 → 先确认它们是不是**都由 `posedge clk` 驱动**
2. 确认 `sel` 的赋值依赖 `sel_cnt` → 是串联关系
3. 推演一个 posedge 上的行为，确认是固有特性

**根因**
两级串联寄存器的固有延迟：

```verilog
always @(posedge clk ...) if (div_cnt == MCNT) sel_cnt <= sel_cnt + 1;   // 第一级
always @(posedge clk ...) case (sel_cnt) 0: sel <= 4'b0001; ... endcase  // 第二级
```

同一个 posedge 上：
- **RHS 求值阶段**：两个块读到的都是**旧** `sel_cnt`
- **NBA 阶段**：`sel_cnt` 写入新值，`sel` 写入基于**旧值**算出的结果
- **下一个 posedge**：`sel` 才根据新 `sel_cnt` 更新

**结论：完全正常，不需要改。**

**经验迁移**
- 看到"A 领先 B 一拍"，**先数中间隔了几级寄存器**，不要急着改代码。
- 判据：若 A、B 都是同一时钟的 `<=` 赋值，且 B 依赖 A → 必然差 1 拍 × 级数。
- **什么时候才需要处理**：当这个延迟真正影响功能时（高速接口、握手协议）。本例中每位保持 1ms = 50000 个 clk，1 拍完全可忽略。
- 想同步的改法是合并 always、用 `sel_cnt + 1` 的新值算输出，但会引入额外组合逻辑，**慢速场景得不偿失**。

### L02. `TURN_FREQ` 设置过高导致 595 数据撕裂

**现象**
`q_sel` 大部分时间正确，但在 `sel` 跳变边沿偶尔出现 `0000`（全灭）或双位同时亮。

**定位过程**
1. 用**值域验证法**：干净一热码率只有 90.4% → 确实有问题
2. 观察错值出现的位置 → **都集中在 `sel` 跳变边沿** → 指向"采样窗口"问题
3. 用**反证法**：改 `TURN_FREQ` → 错值率骤降 → 确认

**根因：两个速率不匹配**

| 量 | 计算 | 值 |
|---|---|---|
| `sel` 切换间隔 | `CLOCK_FREQ / TURN_FREQ` | 50M/1M = **50 clk** |
| 595 一帧传输耗时 | 16 bits × 4 clk | **64 clk** |

**50 clk < 64 clk** → `sel` 在"正在被移入 595"的过程中就跳变了，移入的 8 位新旧混合 → 撕裂。

**解决**
`TURN_FREQ` 必须满足：`TURN_FREQ < CLOCK_FREQ / 64 ≈ 781250`
默认 `1000`（每位停留 50000 clk ≫ 64 clk）很安全。

**量化验证**

| TURN_FREQ | 干净一热码率 | 错值 |
|---|---|---|
| 1000_000 | 90.4% | 64 次 `0000` + 32 次双位同亮 |
| 1000 | 98.4% | 仅最初 16 帧（移位寄存器未填满，正常初始化） |

**经验迁移（通用设计原则）**
> 凡是"**串行移位 + 并行锁存**"或任何有**采样窗口**的结构，都必须做这个量化比对：
> ```
> 源数据稳定时间  >  一次完整传输/采样所需时间
> ```
> 设计阶段就把这两个数算出来写进注释，比事后调试省力得多。
>
> 衍生检查项：
> - 移位链越长（级联越多），传输耗时越大，对源数据稳定时间要求越高
> - 若源数据无法长时间稳定 → 需要在传输**开始前先打一拍快照**（双缓冲），而不是边传边读

### L03. 仿真时长不足，"信号一直不动"

**现象**
`q_sel` 一直是 `00000001`，不循环。看起来像位选逻辑坏了。

**定位过程**
1. 确认 `sel_cnt` 确实没变（不是 `sel` 译码坏了）
2. 算 `sel_cnt` 的切换周期
3. 和仿真总时长比对 → 发现仿真根本没跑够

**根因：纯属"假 bug"**

| 量 | 值 |
|---|---|
| `sel_cnt` 切换周期 | 50000 clk × 20ns = **1 ms** |
| 原 tb 总时长 | 4 段 × 200 us = **800 us** |

**800 us < 1 ms** → `sel_cnt` 全程 = 0，`sel` 全程 = `0001`。

**解决**
tb 延时改大：`#2000_00`（200us）→ `#20000_00`（2ms），4 段共 8ms。
改后 `q_sel` 正确循环 `0x01 → 0x02 → 0x04 → 0x08` ✓

**经验迁移**
> **看到"信号一直不动"，第一反应应该是算它的变化周期，而不是怀疑逻辑坏了。**
>
> 检查清单（30 秒就能排除）：
> 1. 这个信号由谁驱动？是计数器还是组合逻辑？
> 2. 若是计数器：位宽多少？分频系数多少？→ 算出切换周期
> 3. 时钟周期多少？→ 换算成实际时间
> 4. 和 tb 的 `#延时 × 段数` 比对
>
> 这三类"看起来像 bug 其实不是"的高频情形：
> - 仿真时长 < 信号变化周期（本例）
> - 信号还处于复位/初始化阶段（移位寄存器未填满）
> - 输出确实正确，但期望值算错了（比如段码表记反了共阴/共阳）

## 二、级联 / 接口类

### L04. ★ 595 级联丢位：`qh_o` 写成寄存器

**这是本次最有价值的案例，值得反复看。**

**现象**
`q_seg` 输出的值**根本不是合法段码**（`0x58 0xD8 0xDC 0xFC 0xC1 0xC7`），看着像段码被"扭曲"了。

**定位过程（关键路径）**
1. **值域验证**：`q_seg` 取值无一在段码表中 → 确认有问题，且不是偶发
2. **分层定位**：`hex8.seg` 本身输出正确 → 问题在 595 链，不在显示逻辑
3. **最小复现**：单独写 tb 测 HC595，确认移位方向是**左移**（`diff <= (diff<<1) | dio`，新数据进 LSB）
4. **逐拍推演** 16 位移位过程，写出每个 srclk 后 `inst0.diff` / `inst1.diff` 的期望值表
5. **比对发现**：`inst1.diff` 实际值 = 期望值**右移 1 位**，`seg[0]` 永久丢失
6. **追问"为什么少一位"** → 级联链上多了一拍延迟 → 定位到 `qh_o` 是寄存器

**根因（原理层面）**

级联连接：`inst1.dio = inst0.qh_o`

```verilog
output reg qh_o;                       // ← 元凶：寄存器
always @(posedge clk ...) begin
  qh_o <= diff[7];                     // ← 在 posedge clk 更新
  diff <= {diff[6:0], dio};
end
```

| | 真实 74HC595 | 寄存器版模型 |
|---|---|---|
| QH' 性质 | **组合输出**（移位寄存器最后一级直接引出） | **寄存器**（`posedge clk` 更新） |
| 下一级采到 | 本级**移位前**的 Q7（靠 QH' 传播延迟保证） | **上一次**移位的值（同一 clk 读到旧值） |
| 结果 | 正确 | **每级联一级丢 1 bit** |

16 位移完后 `inst1` 只收到 `{0, seg[7..1]}`，期望值整体右移 1 位。

**解决**

方案 A（最小改动）：
```verilog
output wire qh_o;        // reg → wire
assign qh_o = diff[7];   // 组合输出
// 删掉复位里的 qh_o <= 0; 和移位里的 qh_o <= diff[7];
```

方案 B（更贴近真实器件，去掉系统时钟采样）：
```verilog
always @(posedge srclk or negedge rstn) begin
  if(!rstn) diff <= 0;
  else      diff <= {diff[6:0], dio};
end
always @(posedge rclk or negedge rstn) begin
  if(!rstn) q <= 0;
  else      q <= diff;
end
assign qh_o = diff[7];
```

两者仿真结果**完全一致**。

**量化验证**

| | 修复前 | 修复后 |
|---|---|---|
| `q_seg` | `0x58 0xD8 0xDC 0xFC 0xC1 0xC7` — **全非法段码** | `0xB0`(3) `0xA4`(2) `0x92`(5) `0x99`(4) `0x83`(B) `0x88`(A) `0xA1`(D) `0xC6`(C) — **全合法段码** |
| `q_sel` | 只有 `0x01` | `0x01→0x02→0x04→0x08` ✓ |

**经验迁移（最重要的一节）**

**① 级联链上的"级间传递信号"必须是组合路径**
```
级间信号如果是寄存器 → 每过一级就多一拍延迟 → 数据错位
```
通用检查：画级联链时，级与级之间传递的那个信号，追问一句"它是 `assign` 还是 `<=`？"

**② 建模外部器件时，传播延迟不是"可忽略的细节"**
真实器件靠传播延迟保证下一级采到旧值；用寄存器建模会破坏这个时序关系。
> 更一般的说法：**"同步采样"会引入 1 拍延迟**。凡是需要"同一时刻两个模块看到同一份旧数据"的场景，都不能用寄存器传递。

**③ 真器件能工作、仿真不行 → 逐条对照 datasheet**
这是定位"模型与器件行为差异"的最快路径。本次就是对比"QH' 是组合还是寄存器"一击命中。

**④ 值域验证法再次立功**
如果一开始就用"输出必须是段码表里的值"这个判据，能省掉大量逐拍推演。

### L05. 用系统时钟采样外部信号会引入额外延迟

这是 L04 的**通用化表述**，单独列出来因为它会在很多场景复现。

**模式识别**
```verilog
// ❌ 常见反模式：用系统时钟去"检测"外部信号的边沿
reg r_ext;
always @(posedge clk) r_ext <= ext_signal;
wire posedge_ext = (~r_ext) && ext_signal;

always @(posedge clk) begin
  if (posedge_ext) ...   // 实际延迟了 1~2 个系统时钟
end
```

**问题**
1. 引入 1~2 拍延迟
2. 要求 `clk` 频率 ≥ 外部信号频率的 2 倍（Nyquist），否则漏检
3. 多个模块采样同一个信号时，各自延迟可能不同步 → 相对时序错乱（L04 的根因）

**正确做法**
- 若信号本就可以作为时钟（如 SPI 的 SCK、595 的 SRCLK）→ **直接用 `always @(posedge ext_signal)`**
- 若必须同步到系统时钟域（跨时钟域处理）→ 用标准的**两级同步器**，并明确接受这 2 拍延迟
- 建模外部器件 → 优先用真实边沿触发，不要"采样"

**经验**
> 每次写 `posedge_xxx = (~r_xxx) && xxx` 时，问自己：
> **"这个延迟会影响功能吗？"** 如果它位于数据通路上（不只是产生一个使能脉冲），大概率会。

## 三、编码 / 建模陷阱

### L06. 位宽不匹配的静默截断（`sel` 4bit vs 8bit）

**现象**
编译告警，但功能"看起来"正常：
```
hex8_HC595_test.v:56: warning: Port 4 (sel) of module hex8 expects 4 bit(s), given 8.
                      Padding 4 high bits of the expression.
```

**根因**
`hex8.sel` 是 `output reg [3:0]`（4 位），但 `hex8_HC595_test.v` 里 `wire [7:0] sel` 是 8 位。
高 4 位**无人驱动** → 波形里显示 `b0xxxx`（高 4 位为不定态）。

**为什么"看起来"正常**
本例恰好只用低 4 位（4 位数码管），高位虽然悬空但不影响功能。这是**运气**，不是设计正确。

**隐患**
- 悬空位在综合后可能被视为无关逻辑被优化掉，行为与仿真不一致
- 若后续扩展到 8 位数码管，高位是 x，直接出错
- 某些工具/目标器件下，不定态传播会导致锁存器推断等意外结果

**解决**
统一位宽，二选一：
- 把 `hex8` 的 `sel` 端口改成 8 位（若计划支持 8 位数码管）
- 把 `HC595_driver` 的 `sel` 输入改成 4 位，移位时少移 4 位（或补 4 个 0 凑齐 8 位）

**经验迁移**
> **编译 warning 是设计缺陷的线索，不要习惯性忽略。**
>
> 高危 warning 清单：
> - `Port N expects X bit(s), given Y` — 位宽不匹配
> - `implicit wire` / `undeclared signal` — 拼写错误或忘记声明
> - `inferred latch` — 组合逻辑分支不完整（if 缺 else / case 缺 default）
> - `constant is truncated` — 常量位宽不够，高位被截
>
> 建议：让每个工程都过一遍 warning，能清零就清零；不能清零的要能说清为什么可以接受。

### L08. ★ 独热码（One-Hot）状态编码：原理、对比与坑位

**是什么**
独热码 = 每个状态用**一个独立的 bit** 表示，任意时刻**只有 1 个 bit 为 1**。n 个状态就需要 n 位状态寄存器。

用户给出的写法（推荐，可读）：
```verilog
localparam STATE_IDLE  = 'b1;      // 当 state 为 [4:0] 时 → 5'b00001
localparam STATE_DELAY = 'b10;     // 5'b00010
localparam STATE_PICK  = 'b100;    // 5'b00100
localparam STATE_FLIP  = 'b1000;   // 5'b01000
localparam STATE_END   = 'b10000;  // 5'b10000
```
⚠️ `'b1` 这种**省略前导零**的写法，实际位宽由 `state` 寄存器宽度决定。若 `state` 是 `[4:0]` 则自动补成 `00001`；**若 state 只声明成 3 位，最后一个就被直接截掉**（见坑①）。

**三种主流状态编码对比**

| 编码 | n 状态所需位数 | 译码方式 | 优点 | 缺点 / 适用场景 |
|---|---|---|---|---|
| 二进制 (Binary) | ⌈log₂n⌉ | 多 bit 比较 | 最省触发器 | 译码组合逻辑大；状态跳变多位翻转 |
| **独热 (One-Hot)** | **n** | **单 bit 判断** | **译码组合逻辑极小、速度快、易调试** | 占触发器多（但 FPGA 不缺） |
| 格雷 (Gray) | ⌈log₂n⌉ | 邻态只变 1 bit | 抗亚稳态/干扰（异步 FIFO 指针常用） | 译码仍偏复杂 |

**为什么 FPGA 上独热码是首选**
FPGA 的触发器（FF）资源远多于 LUT，而状态译码往往是最深的组合逻辑路径。
独热码把"判断当前处于某状态"简化成 `state[2]` 一个信号，**综合器近乎零成本生成**，关键路径短、Fmax 高。
综合器（Vivado / Gowin / Synplify）默认对小状态机就倾向 one-hot，亦可显式指定：
```verilog
(* fsm_encoding = "onehot" *) reg [4:0] state;   // 强制综合器用独热编码
```
SystemVerilog 更推荐用 `enum` 让工具托管编码，可读性最好：
```systemverilog
typedef enum logic [4:0] {
  S_IDLE  = 5'b00001, S_DELAY = 5'b00010, S_PICK = 5'b00100,
  S_FLIP  = 5'b01000, S_END   = 5'b10000
} state_t;
state_t state, next_state;
```

**坑位（重点）**

① **位宽不够 → 静默截断（与 L06 同源）**
5 个状态必须 ≥ 5 位。若写成 `reg [2:0] state;`，`STATE_END='b10000` 被截成 `3'b000`，
和"全 0 非法态"重合，状态机直接跑飞，且编译可能只给 warning 不报错。
✅ 经验：位数 = 状态数；宁多一位别少一位；优先用 `5'b...` 显式常量，别依赖 `'b` 自动推断位宽。

② **非法状态必须兜底**
n 位独热码有 `2ⁿ − n` 个非法值（全 0、多 bit 同置位都非法）。一旦因毛刺/异步复位进入非法态，必须能恢复：
```verilog
function illegal;
  input [4:0] s;
  illegal = (s == 0) || ((s & (s-1)) != 0);   // 全 0 或多 bit 同置位 → 非法
endfunction

always @(posedge clk or negedge rstn) begin
  if (!rstn)               state <= STATE_IDLE;   // 复位进唯一合法初态
  else if (illegal(state)) state <= STATE_IDLE;   // 非法态恢复（防锁死）
  else                     state <= next_state;
end
```
`(s & (s-1)) != 0` 是判断"不止一个 bit 为 1"的经典惯用法（独热校验）。

③ **别把单 bit 标志散落全局**
独热码允许 `if (state[2])` 这种单 bit 判断，但到处散用会丧失语义、改名困难。
✅ 优先 `if (state == STATE_PICK)`，或集中在一个 `case(state)` 里译码。

④ **用 `case(1'b1)` 做独热译码（可选风格）**
```verilog
always @(*) begin
  case (1'b1)
    state[0]: next = ...;   // IDLE
    state[1]: next = ...;   // DELAY
    state[2]: next = ...;   // PICK
    default:  next = STATE_IDLE;
  endcase
end
```
⚠️ 前提：state 一定是合法独热；否则多个分支命中会变得不确定——务必配 ② 的非法态恢复。

**经验迁移**
- 写 FSM 先定编码：**状态少（≤16）且追求速度 → 独热；状态极多/触发器吃紧 → 二进制；跨时钟域指针（如异步 FIFO）→ 格雷。**
- **位数 = 状态数**，截断是静默 bug（呼应 L06 位宽不匹配）。
- **复位 + 非法态恢复**是独热码的最小安全套餐，缺一不可。
- 配合 §0.3 值域验证法：仿真里可断言 `state` 永远是合法独热值之一，能尽早抓出编码错误。

### L09. ★ 矩阵键盘两轮回扫：使能信号时序与"驱动一轴、读另一轴"

**现象**
- `key_board.v` 用 `inout` 三态门 + `key_col_en`/`key_row_en` 两套使能做 4×4 扫描，初看容易搞混"到底先拉高哪个使能"。
- 实测代码（72–91 行）：`STATE_IDLE/END` 里 `key_col_en<=1, key_row_en<=0`；`key_row_en<=1` 直到 `STATE_FLIP` 才出现。**即 col_en 先拉高，row_en 后拉高**——符合"第一轮找行、第二轮找列"的设计。

**原理（根因）**
- 矩阵键盘按键在"行×列"交叉点，只扫一个轴无法唯一定位，必须**两轮**：
  1. **第一轮（IDLE→DELAY→PICKUP）**：列线驱动低（`col_en=1, col_out=0000`），行线高阻浮空（靠上拉为 1）。某键按下 → 所在行被列 0 拉低 → 读 `key_row_in` 得**行号**。
  2. **第二轮（FLIP→END）**：行线驱动低（`row_en=1`，且 `key_row_out` 恒 `0000`），列线高阻浮空。按键把所在列拉低 → 读 `key_col_in` 得**列号**。
- **铁律：任意时刻只驱动一个轴，另一个轴必须高阻浮空**。两轴同时驱动就失去判别能力，且 PICKUP→FLIP 切换就是"先撤 col_en、再上 row_en"，中间没有两轴同驱的瞬间。
- **先扫列还是先扫行只是约定**，本模块选"先扫列找行"，换成"先扫行找列"也行，只要两轮一致即可——别被"教科书先扫行"的印象误导。

**PICKUP 的易错细节**
- PICKUP 只把 `col_out` 从 `0000` 翻成 `1111`（助攻被拉低的行快速回升，注释点出 FPGA 内部上拉弱、回升慢），**但 `col_en` 仍为 1、`row_en` 仍为 0**。直到 FLIP 才撤 col_en、拉 row_en。**采样发生在列回升之前**（进 PICKUP 当拍 col_out 还是 0，行仍被拉低），所以读到的 `row_in` 是对的。

**经验迁移**
- 任何"双向/复用引脚 + 方向切换"的接口（I²C、SPI 半双工、矩阵键盘、总线仲裁）都遵循同一铁律：**方向切换时先撤旧方向使能、再开新方向使能，避免同驱冲突**。
- 看这类代码先画"使能 x 状态"时序图（见对话内 SVG），一眼就能确认每轴在何时被驱动、何时被读。

### L10. ★ 仿真矩阵键盘：testbench 的驱动顺序与 DUT 是**镜像**关系

**现象**
- `top_tb.v` 里 `key_row_en = 1`（line 58）**先于** `key_col_en = 1`（line 71）拉高，与 `key_board.v` 状态机"col_en 先拉高"**相反**。初学者容易以为 tb 写反了。

**原理（根因）**
- DUT（`key_board.v`）是**扫描主控**：主动驱动一个轴、读另一个轴。第一轮驱动**列**(col_en=1)读**行**，第二轮驱动**行**(row_en=1)读**列**。
- tb 扮演**键盘（被动开关）**：没有真实开关模型时，要"模拟按键"只能**驱动 DUT 正在读的那一侧**（浮空侧），让 DUT 看到该线被"开关"拉低。
- 所以：**DUT 读行时（第一轮）tb 驱动行 → key_row_en 先拉；DUT 读列时（第二轮）tb 驱动列 → key_col_en 后拉。** 两者是**镜像**，DUT 的"驱动轴"= tb 的"驱动轴"永远错开，故看起来顺序相反——**不是 bug**。

**⚠️ 但本工程 tb 另有两个真问题（不修跑不出干净波形）**
1. **时序未同步**：tb 用固定 `#1000`/`#100` 延迟，与 DUT 被 `defparam KEY_JUDDER='d2000` 加速后的 2000 周期消抖 / 5 态流转对不齐，可能驱动在错误相位。
2. **值不对**：`key_row_out = 4'b0001` 把 row1/2/3 全拉低 = 模拟了 3 个键；单键应只拉低被按键所在行、其余浮空（如 `4'b1110`）。`wait(key_col==4'b1111)` 等待 DUT 浮起列线（进第二轮），时序脆弱易挂起。

**经验迁移**
- 给"双向/三态 + 主从角色"的接口写 tb：**先厘清谁是从（被动）**，从端驱动的永远是主端正在读的那一侧，顺序天然与主端镜像。别被表面顺序迷惑。
- 更稳的做法是**建模真实开关**：`assign key_row[r] = (pressed && key_col_en) ? key_col[c] : 1'bz;`（仅按键且主端驱动列时才把行连到列），让 tb 完全被动，由 DUT 的使能信号驱动行为，彻底消除"固定延迟对不齐"的问题。

## 四、可迁移的设计原则（写代码时的 checklist）

每次写新模块，过一遍：

**时序与接口**
- [ ] 这个信号的采样窗口够长吗？（源稳定时间 > 传输耗时，见 L02）
- [ ] 级联/级间传递的信号是组合路径吗？（见 L04）
- [ ] 有没有用系统时钟去采样本可以作为时钟的外部信号？（见 L05）
- [ ] 跨时钟域的地方用了标准同步器吗？
- [ ] 串联寄存器导致的 1 拍延迟，功能上能接受吗？（见 L01）

**编码规范**
- [ ] 所有端口位宽和连接 wire 位宽一致吗？（见 L06）
- [ ] `case` 有 `default` 吗？`if` 有 `else` 吗？（避免推断锁存器）
- [ ] 复位是同步还是异步？两种风格有没有混用？
- [ ] 参数是 `parameter` 还是 `localparam`？被 `defparam` 引用的参数若删除，所有引用处都同步改了吗？
- [ ] 状态机编码选对了吗？独热码位数 = 状态数（见 L08）
- [ ] 独热码有"复位进初态 + 非法态恢复"吗？避免锁死（见 L08）

**仿真验证**
- [ ] tb 里有 `$finish` 吗？
- [ ] 仿真时长覆盖了所有计数器的完整周期吗？（见 L03）
- [ ] 输出是否落在"合法值集合"里？（段码表 / 一热码 / 枚举值，见 L04）
- [ ] 有没有修复前后的量化对比？

**建模外设**
- [ ] 输出是组合还是寄存器，对照 datasheet 确认了吗？
- [ ] 时序参数（建立/保持时间、传播延迟）是否体现？

## 五、上板硬件调试

### L07. ★ 原理图引脚核对：DIG2/3 被走到 SSPI 专用脚

**现象**
仿真波形完全正确（段码、位选、扫描都无误），但上板后：
- 只有 2 位数码管有显示，`sel[3:2]` 怎么约束都失败，工具报"该引脚是 sspi，不能用于普通 IO"
- 段码看着"对不上"，但**亮度会随显示内容变化**（说明数据确实出去了，只是映射/选通有问题）

**定位过程（关键：从 PDF 原理图提取引脚对应）**

1. **先确认仿真没问题**——排除代码逻辑，把范围锁定到硬件/引脚（见 §0.1 分层定位）
2. **从原理图 PDF 提取文本**，确认数码管相关的网络名：
   - 扩展板：`7SEG_4B_LED`（4 位 7 段）
   - 段选：`SEG0`~`SEG7`
   - 位选：`DIG0`~`DIG3`
3. **提取带坐标的文本，按"同列"匹配** 网络名 ↔ IOB 标识：

   | 网络 | IOR 标识 | FPGA 引脚 | 用户 .cst | 结果 |
   |---|---|---|---|---|
   | SEG0 | IOR34B | K16 | `q_seg[0]=K16` | ✅ |
   | SEG1 | IOR34A | L16 | `q_seg[1]=L16` | ✅ |
   | SEG2 | IOR43A | H20 | `q_seg[2]=H20` | ✅ |
   | SEG3 | IOR43B | G20 | `q_seg[3]=G20` | ✅ |
   | SEG4 | IOR45A | J22 | `q_seg[4]=J22` | ✅ |
   | SEG5 | IOR39A | K17 | `q_seg[5]=K17` | ✅ |
   | SEG6 | IOR45B | H22 | `q_seg[6]=H22` | ✅ |
   | SEG7 | IOR52A | M15 | `q_seg[7]=M15` | ✅ |
   | DIG0 | IOR39B | J17 | `q_sel[0]=J17` | ✅ |
   | DIG1 | IOR50B | L13 | `q_sel[1]=L13` | ✅ |
   | **DIG2** | **IOR63B** | **M22（SSPI_CS_N）** | — | ❌ **专用脚** |
   | **DIG3** | **IOR63A** | **N22（SSI0/SI）** | — | ❌ **专用脚** |

**根因**
PCB/原理图把 `DIG2`、`DIG3` 走线到了 FPGA 的 **SSPI 配置引脚**（M22 / N22）。这两个脚是给配置 Flash 用的，**硬件上就是专用脚，无法当普通 IO**，工具会直接拒绝约束。

⚠️ 同类的 Bank 5 SSPI 脚（都不可用）：`N22`(SI/SSI0)、`M22`(SSPI_CS_N)、`M18`(SO/SSI1)、`L18`(SSPI_CLK)

**解决（不能改板/飞线时，纯软件绕过）**

① **位选改成 2 位扫描**，消除 `sel_cnt=2/3` 时的空白拍（否则每 4ms 有 2ms 全灭，会闪）：
```verilog
// hex8.v：译码和数据选择都只取 sel_cnt[0]
case (sel_cnt[0])
  0: sel <= 4'b0001;
  1: sel <= 4'b0010;
  default: sel <= sel;   // 补 default，避免推断锁存器
endcase
```

② **自动翻页**，让 2 位数码管分时看全 4 个数字：
```verilog
// 顶层：每 1 秒交换高低字节
reg page; reg [29:0] page_cnt;
always @(posedge clk or negedge rstn) begin
  if (!rstn) begin page <= 0; page_cnt <= 0; end
  else if (page_cnt == 50_000_000) begin page_cnt <= 0; page <= ~page; end
  else page_cnt <= page_cnt + 1;
end
wire [15:0] disp_data_page = page ? {disp_data[7:0], disp_data[15:8]} : disp_data;
```

③ **段序排查**（若段码显示错乱）：用固定图案测出 bit↔段 映射
```verilog
assign seg = (sw == 2'b00) ? 8'b1111_1110 :   // 仅 bit0=0
             (sw == 2'b01) ? 8'b1111_1101 :   // 仅 bit1=0
             (sw == 2'b10) ? 8'b0111_1111 :   // 仅 bit7=0
                              8'b0000_0000;   // 全 0（共阳应全亮）
```
- `sw=11` 全亮 → 共阳确认、硬件连通
- `sw=00` 亮 **a 段** → 段序正序（`bit0=a … bit7=dp`），段码表没问题
- `sw=00` 亮 **dp** → 段序反了 → 改法：把 `.cst` 里 `q_seg[7:0]` 的 8 个引脚**反序重排**（不动 RTL）

**经验迁移**

> **① 拿到新板子，先做"专用引脚清单检查"**
> 把原理图上所有专用脚（SSPI/JTAG/配置/时钟/差分专用）对应的网络名列出来。
> 正常情况应该只有 `NULL`、`SSPI_*`、`TCK/TMS/TDI/TDO` 之类；
> **如果出现 `SEG*`、`DIG*`、`LED*` 这类业务网络名 → 一定是设计错误**，趁早发现。

> **② PDF 原理图是矢量文本时，可以用脚本提取核对**
> 本次用 Python `zlib` 解压 PDF 内容流 → 提取 `(text)Tj` 及其 `Tm` 平移坐标 →
> 按**同行（y 接近）**或**同列（x 接近）**把"网络名 ↔ IOB 标识 ↔ 引脚号"关联起来。
> 脚本见 `fst_analysis/pdf_xy.py`、`seg_map.py`。
> ⚠️ 局限：连线是矢量图形无文本，跨页（连接器页 vs Bank 图页）的关联需要人工判读或靠同列坐标匹配。

> **③ "亮度有变化但显示不对"是重要线索**
> 说明数据链路是通的（段码在变），问题在**映射关系**（段序）或**选通**（位选），
> 而不是"完全没输出"。这个判据能快速缩小范围。

### L11. ★ testbench 激励跳变必须避开时钟沿（采样竞争）

**现象**：`edge_detect` 仿真中，把 `sig_in` 的跳变点设在时钟上升沿
（如 clk 沿在 150ns，`sig_in` 也在 150ns 赋值），结果 DUT 里打拍寄存器
`d1` 与输入**同拍**变化——看起来"0 拍延迟"就出了边沿脉冲，掩盖了
真实的 2 拍流水。

**原因**：TB 的 `initial` 赋值与 DUT 的 `always @(posedge clk)` 在同一时刻
竞争；iverilog 的调度使非阻塞采样读到了新值，等价于"输入与时钟对齐"。
真实世界的异步输入不会与时钟严格对齐，这种对齐在**上板后不可能复现**，
仿真结果反而误导。

**解决**：TB 中把输入跳变点放在**两个时钟沿之间**（如 20ns 周期时钟，
跳变设在 t=155 而非 t=150），观察真实打拍链：sig_in → d1（下一沿）→
d2（再下一沿）→ 边沿脉冲。

**经验迁移**

> 写 TB 时问自己：激励变化点是不是恰好撞上时钟沿？是就挪开半个周期。
> 判断打拍类 DUT 是否正确，看"输入变化到第一级寄存器变化"应隔 1 个
> 时钟周期，而不是同拍。

### L12. ★ 单周期脉冲信号（done/valid）必须"边沿时刻断言"，不能事后查询

**现象**：`uart_rx_fsm_demo` 仿真对 `rx_done`（单周期脉冲）用
"发送完 #200 后 if(rx_data==期望 && rx_done)" 断言，结果误报 FAIL——
`rx_done` 只高 1 个 clk，查询时早已落下。

**原因**：单周期脉冲的性质是"只在边沿后的那一个周期为高"，
**事后电平查询永远读到 0**，与功能无关。

**解决**：用 `always @(posedge clk)` 在 `rx_done` 为高的**那一拍**捕获
`rx_data` 并比对；多帧时用 `frame_cnt` 区分第几帧，避免多个 if 同时命中
造成误报。

**经验迁移**

> 凡是单周期使能/完成信号，断言一律"打拍捕获"，并注意多个断言分支
> 要互斥（case 或 if-else 链），否则一帧同时命中两个分支产生假 FAIL。

### L13. UART RX 起始位处理：STATE 必须数满整个起始位再采数据位

**现象**：FSM 初版 `S_START` 只数到 BIT_CLKS/2（起始位中点）就跳 `S_DATA`，
数据位采样点落在起始位边界附近，鲁棒性差（本仿真恰好通过，改时序会翻车）。

**原因**：起始位从下降沿起占满 BIT_CLKS 个时钟，若提前离开起始位，
后续每个数据位的采样窗口整体前移，中点采样退化为边界采样。

**解决**：`S_START` 数满 `BIT_CLKS-1` 再进 `S_DATA`（对齐到数据位起点），
数据位内采样点取 `BIT_CLKS/2`（稳定区）而非边界。

**经验迁移**

> 协议类状态机，先把"每一位占多久、从哪拍对齐"用数值表格推演一遍
> 再写码；采样点选在 bit 的稳定区（中点附近），不要选跳变边界。

### L14. ★ UART 收发的"位序"陷阱：LSB 先发 ≠ 移位寄存器的天然顺序

**现象**：`uart_rx` 首版用移位寄存器 `shift_reg <= {shift_reg[6:0], rx_d2}`
收 8 位（LSB 先发），收 0x69 却得到 0x96；而第二帧 0xA5 恰好"通过"。

**原因**：
1. 发送端 LSB 先发，线序是 bit0→bit7；
2. 接收端若每次把新位**从低位移入**（`{旧[6:0], 新}`），则第 1 个到的 bit0
   会被后续 7 个新位"顶"到最高位——最终 shift_reg[7]=bit0，正好位反序；
3. 0x69=0110_1001 反序 1001_0110=0x96 → 错；0xA5=1010_0101 是**回文**
   （反序还是自己）→ 假通过，掩盖了 bug。

**解决**：既然知道第 i 个到达的 bit 就是 bit_i，**按位号直接写入**：
`rx_data[bit_cnt] <= rx_d2;`，不需要移位寄存器。或移位方向选对
（新位进 MSB）后整体反转，但直接写最直观。

**经验迁移**

> ① 收发协议务必写明"哪端先发/哪端先收"，位序错了不报错、结果也"看起来对"；
> ② 选测试数据要防"回文陷阱"：0x55/0xA5/0xFF/0x00 这类对称码测不出位序 bug，
>    用 0x69/0xB4/0x3C 这类非对称码；
> ③ 移位寄存器方向（左移右移、新位进哪端）决定最终位序，动手前先画一遍。

### L15. ★ 断言状态机要跳过"流水线建立期"，否则开头几拍假 FAIL

**现象**：`adc_capture`（3 级打拍）TB 断言"输出每拍 +1"，但开头 3 拍
（数据还没流过流水线）总是 FAIL：输出 512（复位后初值）被拿去和
断言自己的期望计数器比，期望 513 而实际还是 512。

**原因**：DUT 的流水线有建立延迟（数据从输入到输出需 N 拍），
但断言状态机从复位后第 1 拍就开始比较 → 比较的是"空转期"的输出。
**DUT 完全正确，是断言没等数据流建立。**

**解决**：
1. 断言前先等 `valid` 拉高（数据已开始流动）；
2. 再跳过前 N 拍建立期（N = 流水线级数）；
3. **更稳的做法**：用"黄金参考模型"——例化一个理想的 N 拍延迟器
   把输入延迟 N 拍后与 DUT 输出逐拍比较，无需手工数拍。

**经验迁移**

> "DUT 输出初值保持"不是 bug，是流水线建立期的正常现象。
> 写流水线模块的 TB 时：valid 就绪 + 跳过建立期 + 或黄金参考模型，
> 三者取一，别让断言在空转期报假 FAIL 浪费时间。

### L16. ★ 无符号减法会"吃掉"负数：减中点必须用 signed

**现象**：`vpp_measure` 用 `signed_in = {1'b0,data_in} - 512` 把 0~1023 码
"减去中点"得到 ±512 的带符号值。仿真中负半周的 -78 变成 **1970**，
max 追踪被污染，Vpp 错成 946（应 800）。

**原因**：减法双方都是无符号 → `112 - 512` 按无符号模运算 = 补码大正数
（2048-400=1648 之类），没有负号概念。后续 `if (signed_in > cur_max)`
用无符号比较，把补码大正数当成了新最大值。

**解决**：涉及"减中点/减偏置后可能为负"的运算，信号必须声明 signed：
```verilog
wire signed [DATA_W:0] signed_in;
assign signed_in = $signed({1'b0, data_in}) - $signed(MID_CODE[DATA_W:0]);
reg  signed [DATA_W:0] cur_max, cur_min;   // 比较双方都要 signed
```
Verilog 比较的符号性**由操作数的 signed 属性决定**——一个 signed 一个
unsigned 时按 unsigned 处理，必须双方 signed 才有符号比较。

**经验迁移**

> ① "数据减直流中点再跟踪峰谷"是 Vpp 测量标准做法，但**减出来的负数
> 必须 signed 承载**，否则下界（min）追踪直接失效；
> ② 凡是做带符号算术（减法可能为负、累加可能溢出到负），先检查信号
> 有没有声明 `signed`；
> ③ 无符号补码的典型症状：某信号"忽然跳到大正数"（≈2^N-小值），
> 第一反应查它是不是负数被无符号化。


### L17. ★ Verilog 乘法精度 = max(操作数位宽)——16bit×16bit 会溢出
**现象**：fft64 蝶形 400×16384（Q14 旋转因子）结果算成 0/乱值，频谱全近零。
**根因**：`br * wc` 中 br、wc 都是 16bit reg——Verilog 规定算术运算按**最大操作数位宽**计算，
16bit×16bit 只保留低 16bit（400×16384=2^23 截断为 0）。
**解决**：乘前把操作数符号扩展到 32bit：
```verilog
reg signed [31:0] br32;  // 读入时扩展
br32 <= $signed({{16{rm[jj][15]}}, rm[jj]});
// 再乘：br32*wc32 精度 32bit，2^23 结果安全
```
**经验**：涉及乘法的定点 RTL，先心算"乘积最大需要多少位"，把任一操作数扩到足够宽。

### L18. $readmemh 是相对路径——换目录跑就"悄悄全 x"
**现象**：P14 单独仿真全过；P15 联调（换到 phase15 目录跑）FFT 输出全 x。
**根因**：`$readmemh("twiddle_cos.mem")` 按**运行目录**找文件；phase15 下没有该文件，
iverilog 只 warning 不报错，ROM 保持 x。
**解决**：跨目录联调先 `cp` 需要的 .mem；或设计时约定所有 .mem 放工程根、用 `+incdir`。
**排查信号**：仿真输出 x 且编译无 error → 先查 $readmemh 文件路径。

### L19. TB 断言 reg 未初始化 = x 的隐蔽陷阱
**现象**：top_system_tb 里 `reg vpp_seen;`（未赋 0）→ `if(!vpp_seen)` 永远不真，
首窗污染值 712 被当成有效结果；`while(!got_line)` 因 got_line=x 直接跳过等待。
**根因**：reg 初值 x；x 参与 if/while 判 false，逻辑分支"看起来没执行/提前退出"。
**解决**：TB 里所有控制 reg 声明即赋初值（`reg x=0;`）或在 initial 里清零。
**经验**：仿真行为怪异先怀疑未初始化 reg——这也是可综合代码必须同步复位的原因之一。

### L20. double-dabble（二进制→BCD）三坑
**现象**：report_tx 把 800 转成 670731、只发最后一通道、数字缺个位。
**根因/对策**（三处都踩过）：
1. **加 3 后要整体左移**：`bcd <= {bcd_adj[22:0], bin_s[19]}`，不是原位替换各 nibble；
2. **每通道独立保存结果**：串行转换会覆盖 bcd，4 通道须各存一份（bcd_v/p/b/m）；
3. **位组要处理 5..0 全 6 位**：最低位（个位）若漏掉，203 会变 20；
   且下一个通道开始前 bcd 清零 + 前导 0 跳过用"通道内"标志而非全局计数。
**验证建议**：BCD 类模块先独立 TB 用边界值（0、9、99、800、203）核对字符串。

### L21. 带直流偏置的 ROM/ADC 数据 ≠ 补码：先无符号扩展再减中点
**现象**：wave_dds 幅度缩放里，ROM 输出 990 减 512 得到 -546（应 +478），
输出被钳到 0~510。
**根因**：波形 ROM 存的是 0~1023 **无符号二进制码**（中心 512，偏置编码），
不是有符号补码。我按 bit9 做符号扩展：990(0b1111011110) bit9=1 → 被当
signed 10bit 的 -34，再减 512 = -546。>511 的"正半周"全被当成负数。
**解决**：先**无符号扩展**再减中点：
```verilog
diff32 = $signed({22'd0, rom_out}) - 32'sd512;   // rom∈[0,1023] → diff∈[-512,511]
```
**判别口诀**：凡是"码=中点+幅度×波"的偏置编码（ROM 波形表、多数 ADC 二进制码），
必须无符号看待；只有真正的补码流（如 ADC 输出本来就带符号）才符号扩展。

**同族陷阱补充（L17 姊妹）**：`32'd656` 这类**无符号字面量**一旦混进 signed
乘法链，整个表达式被拖成无符号 → `>>>` 变逻辑右移、结果钳位到 1023。
常量一律写 `32'sd656`。

### L13. 示波器看到"近似直线 + 频率读数极低" = 转战数字侧查 DDS/ROM/时钟

**现象**：DAC OUT 接示波器，调到 20us/div 后看不到正弦，反而是一条近似直线；
屏幕频率读数只有 21Hz/9.9Hz 量级，远低于目标 100kHz。
**判断**：这说明 DAC 输出端有电压变化（运行 vs 不运行不同），但**不是目标正弦波**。
大概率是 FPGA 数字侧只输出了一个恒定或极低频的码值。
**定位顺序**：
1. Gowin ChipWatcher 抓 `da_clk`（应翻转）、`da_data[9:0]`（应每拍变）、DDS 相位累加器（应线性递增）

3. 若 da_data 恒定：**高云实测最大坑——行为级 `$readmemh("xxx.mem", rom)` ROM 上板常不把外部文件数据加载进 bitstream**，
   ROM 变全 0 → DDS 输出恒定 → DAC 一条直线。修法：① 用高云 pROM IP（Tools→IP Core→pROM）加载 .mem；
   ② 或把 512 点数据直接内嵌到 `initial` 块 / `case` 里（数据进源码，彻底避开外部文件路径问题）。
4. 若相位累加器不增：查 `fword`（频率控制字）是否被正确送入顶层

### L22. ★ DAC 锁存边沿与数据更新边沿重合 → 正弦波周期性尖锐毛刺

**现象**：DDS→ADA107(3PD5651E) DAC 输出 100kHz 正弦，主体连续平滑，但叠加大量"窄、幅度大、向下"的尖峰；
示波器自动频率被毛刺误导读成 ~300kHz（实际光标量周期≈10μs=100kHz，二者一致）。
**定位过程**：
1. 先按手册确认真实频率：时基 2μs/div × 相邻峰 5 格 = 10μs → 100kHz，与 DDS FREQ_WORD(0x83126F@50MHz) 吻合；**不动频率字**。
2. 读 ADA107 手册 P7 原文："数据在时钟的**上升沿锁存**，**可以在时钟的下降沿发送数据**，这样使 DA 芯片在数据的中央采样"。
3. 查 dac_driver.v：`assign da_clk=clk; always @(posedge clk) da_data<=data_i;` → **数据更新边沿与 DAC 锁存边沿完全重合，零建立/保持裕量**。
4. RTL 仿真量化（iverilog+FST，自检器测"da_data 跳变距 da_clk 上升沿距离"）：当前代码 136 次违例（每次跳变距上升沿 0.00ns）。
5. 排除数字逻辑毛刺：DDS ROM 输出 `dout<=rom[addr]` 已寄存 1 拍，dac_driver 再寄存 1 拍 → 整条 da_data 通路全程寄存，无组合逻辑直驱。
**解决（按手册，最小改动）**：仅把 dac_driver 数据寄存器触发边沿改为 `always @(negedge clk)`（da_clk 仍=clk 上升沿锁存）。
修改后仿真违例 136→1（仅上电后第一次跳变，非周期性），da_data 在锁存前稳定半周期（50MHz 下半周期=10ns >> tS2ns/tH1.5ns）。DDS 频率/波形不变（data_i 仍 posedge 更新，仅多 0.5 拍延迟）。
**经验迁移**：
① 所有"源同步"并行接口（DAC/ADC/外部 SRAM）必须先读手册确认锁存边沿，让 FPGA 数据在"非采样边沿"更新，拿满半周期裕量；
② 示波器自动频率被毛刺误导时**不要改频率字**，改用光标量周期判断；
③ 数据通路全程寄存可快速排除"组合逻辑毛刺"假设；
④ **无 SMA/BNC 探头也能验证**：用板载 CP2102 UART(引脚 AB20) 把 da_data 以 ASCII 发到 VOFA+(Firewater)，PC 上直接看数值波形是否干净。
**关联**：本次新增 `src/dds_uart_bridge.v` + `top_dds_dac_uart.v` 即该验证法；DAC 驱动修复见 `src/dac_driver.v`。

### L23. 降速反而更乱：UART RX 分频计数位宽不够（BAUD_DIV>63 溢出）
**现象**
排查 1M 串口上位机乱码时，把波特率从 1M(`BAUD_DIV=50`) 降到 500k(`BAUD_DIV=100`)，
结果**回显从能解出 0x57('W') 变成 0x00**——"降速反而更坏"。
**定位过程**
1. VCD 位流核对：DUT 的 `uart_tx_out` 波形完全正确（500k 位宽、数据位对），排除 TX 与注入问题；
2. 反向追到 RX：收到字节全 0 → 是 `uart_rx` 把注入的 'W' 解成了 0x00；
3. 读源码：`uart_rx.v` 的位内计数 `reg [5:0] clk_cnt` 上限 63，且比较都写 `BAUD_DIV[5:0]`——`BAUD_DIV=100` 被截成 `36`，采样点全错位。
4. 为什么 1M 一直"正常"：`BAUD_DIV=50 < 64` 恰好放得下，bug 被掩盖。
**解决**
`uart_rx.v`：`clk_cnt` 6bit→16bit，删除全部 `[5:0]` 截断（`START_MID`/`MID_CNT`/`BAUD_DIV` 比较直接用全宽）。
改后 500k 仿真 PASS（回显 0x57 精确）；1M 不受影响。
**经验迁移**
① 任何**分频计数器的计数/比较位宽必须 ≥ 可能的最大分频值**；6bit 只能到 63，改参数前先心算 bit 够不够；
② "降速/改参实验反而更坏" → 第一反应查**位宽截断**，而不是继续怀疑原假设；
③ 共享模块（如 `uart_rx.v` 被 top_system/selftest/多个 top 复用）改位宽是**兼容升级**，但要全工程重编复核。

### L24. ADC 同相采样裕量偏小：3PA1030 tOD=25ns vs 50M 周期 20ns
**背景（非突发 bug，是设计要点）**
`top_system` 当前 `ad_clk_out = clk50`（与 ADC 采样同相）。3PA1030 数据在 ad_clk 上升沿后 **tOD=25ns** 才稳定，而 50MHz 周期仅 20ns。
**分析**
- 同相采样时，posedge clk50（=ad_clk 上升沿后 20ns）采到的其实是"上一采样值"（数据在 25ns 才变）→ **功能可用**，但建立/保持裕量偏小（保持余量仅约 5ns）。
- 官方 A7Lite 例程用 **180° 相移时钟**采样，把采样沿推到数据有效窗口中心，裕量最大。
**经验迁移**
① 上板若 ADC 读数抖动 / 跳变 / 偶发错码，**优先查采样时钟相位**，而非改逻辑（逻辑仿真已 PASS）；
② 高云侧正解：用 PLL 出 `ad_clk` + `ad_clk_180deg` 两路（即 P6），采样用 180° 那路；
③ 任何"流水线 ADC + FPGA 同源时钟采样"都要先算一遍 tOD vs 周期，确认建立/保持裕量够。

### L26. FFT 主峰搜索加幅度门限（过滤噪声/弱信号虚假峰）
**背景（题2 fft_peak 改进，2026-09-09）**
原 `fft_peak` 只在 bin1..N/2-1 找 |re|+|im| 最大者输出，无信号/纯噪声时也会挑出一个"最大噪声 bin"报给上层，
造成 VOFA+ 上凭空出现一条虚假主频线、且 `bin` 字段乱跳。
**定位/解决**
- 加 `MAG_THRESHOLD` 参数（默认 40，单位 |re|+|im|）：扫描完成时若 `best_mag < 阈值` → 判无有效主峰，`peak_bin=0`、`peak_mag=0`；否则输出真峰。
- 验证：TB 注入"±8 LSB 白噪声"应得 bin=0；注入 500k/200LSB 正弦应得 bin=16/mag≈125。iverilog 实跑双场景 ALL PASS。
**经验迁移**
① 任何"峰值/最大者检测"在噪声环境下都要先设幅度门限，否则会输出随机噪声峰；
② 门限用参数化、默认保守值；真实弱信号（如题4 100mVpp）若 mag<阈值会被诚实判"无信号"，这比乱报更对（也提示该信号需要前端增益）；
③ 阈值标定靠实测：用仿真看"无信号噪声 mag"与"最小可用信号 mag"的间隙，取中间值最稳。

### L27. 行为级 FFT 仿真全对、上板错乱 → 换厂商 IP 核
**背景（题2 FFT 修复，2026-09-09 22:00）**
自写 64 点 DIT FFT（`fft64.v`）在 iverilog 仿真下 100% 通过（tb_top_analysis 双场景 PASS、tb_fft64_mag
各种输入 mag 量级都对），但上板后**`bin` 在 3~30 跳、`mag` 恒定 4~5 万**。
前期 4~5 小时按"调 PLL 采样相位（180°→270°）、怀疑 PLL 失锁、查 ADC 跨时钟域"等方向排查，全部南辕北辙。
**根因**
行为级 RTL（双端口 RAM 数组 `rm[64]/im[64]` 读写、`initial` 初始化 `wcos[64]/wsin[64]` twiddle ROM、
蝶形内部 32bit 乘法）在 iverilog 仿真与 FPGA 综合后的行为可能严重不一致：
- RAM 推断为 BSRAM 后双端口读写时序与 always 块行为差异
- initial 块在实机 ROM 内容异常（仿真正常 iverilog 跑 initial）
- 32bit 乘法被综合器优化/简化导致 >>14 截位错位
- 任何 `reg [N:0] array [0:M]` 在 `always` 块中读写的综合行为都需警惕
**定位（关键步骤）**
写**隔离测试顶层** `top_fft_test.v`——内部计数器直接产生 500kHz 方波喂 `fft64`（完全绕开 ADC/PLL/信号源），
上板看 bin/mag：
- **若 bin=16 稳定、mag≈400** → FFT 正常，问题在 ADC 链
- **若 bin 仍乱跳、mag 仍 5 万** → FFT 自身问题，与外部无关
隔离测试结果是后者 → 100% 锁定 fft64 上板行为错乱，不需要再去怀疑 ADC 链。
**修复**
换高云 FFT IP（IP Generator 选 FFT：64点 Fixed/Forward/Natural/RS111/16bit/DSP/EBR），
写 `fft_wrapper.v` 适配（接口与自写 fft64 完全一致——`fft_peak`/`top_system` 零改动）：
- 慢速采集（din_valid 稀疏）→ RAM 缓存 64 点 → 拉 start → `ipd=1` 期间 burst 喂给 IP
- `opd=1` 转发 64 拍（idx==63 结束）→ 回采集
- 协议参考官方 `C:\Gowin\...\IDE\data\examples\FFT\src\testfft_top.v`（**ipd 是 IP 输出"接收中"信号**）
- rst 高有效（顶层 sys_rst_n 低有效需反相）
**验证**
隔离测试 top_fft_test+fft_wrapper 上板：**bin=16 稳定、mag≈398**，与仿真预期完全一致。
top_system 换 fft_wrapper 后 100kHz 实测：`vpp≈453、period=500、bin=3 稳定、mag≈58`——全部正常。
**踩坑**
- `buf` 是 Verilog **保留关键字**（缓冲门原语），做数组名 iverilog/Gowin 都会报"Syntax error in variable list" → 改名 `wbuf`
- FFT IP 主体加密，iverilog 仿真不了（写行为替身 `tb_fft_model.v` 仅验证 wrapper 握手逻辑不卡死/不丢点）
**经验迁移**
① **"仿真全对、上板乱跳"是行为级 RTL 的经典坑**——双端口 RAM 数组读写、`initial` 块初始化、32bit 乘法综合后行为都可能与仿真不一致
② **隔离测试是最快的根因定位器**：写一个"用内部已知信号源替代外部输入"的最小顶层，把问题二分到"被测模块"或"外部链路"
③ **不要陷入"调外围补偿内部 bug"的陷阱**：之前一直调 PLL 相位试图让 fft64 看着像对的，纯属白费；功能模块行为不对时**果断换 IP/重写**
④ 任何复杂算法（FFT/FIR/CORDIC/DDS）自写前先评估厂商 IP：开发时间、综合资源、性能都更优；只在"IP 不支持的特殊场景"才自写
⑤ 仿真与综合的行为差异是"行为级 RTL 永远甩不掉的影子"——把仿真当作设计的"草稿"，上板验证才是"定稿"

### L28. 顶层直读 PLLx 域寄存器 Q 端 → 偶发亚稳，vpp 1024 窗口偶发塌陷

vpp_measure / freq_measure / fft_wrapper 全是 `clk50` 域 → 顶层**直读 pll_clk1 域**。
PLL 同源 180°=10ns 相位差，理论 setup/hold 余量够，但实机亚稳偶发（PCB 走线延迟、PLL 输出抖动
可能让余量<8ns），1024 窗口内多个点被打到错误值 → max-min 突然变小。
**修复（最小改动）**
顶层在 `clk50` 域加 2 拍同步寄存器，把所有下游（vpp_measure / freq_measure / fft_wrapper / 直通
DAC pass_code）改用 `adc10_sync` / `adc_valid_sync`；`adc_capture` 自身接口不变。
```verilog
reg [9:0] adc10_s1, adc10_s2;
reg       adc_valid_s1, adc_valid_s2;
always @(posedge clk50 or negedge sys_rst_n) begin
    if (!sys_rst_n) begin adc10_s1<=0; adc10_s2<=0; adc_valid_s1<=0; adc_valid_s2<=0; end
    else begin
        adc10_s1 <= adc10; adc10_s2 <= adc10_s1;
        adc_valid_s1 <= adc_valid_w; adc_valid_s2 <= adc_valid_s1;
    end
end
wire [9:0] adc10_sync     = adc10_s2;
wire       adc_valid_sync = adc_valid_s2;
```
**经验迁移**
① 同频异相（PLL 输出 0°/180°）模块输出被另一时钟域读时，**顶层必须显式同步**（≥2 拍），
不能信"同源 PLL 余量够"
② 偶发数据塌陷（max-min 突然变小、或某字段跌到非法值）= 1024 窗口内大量点异常 = 跨时钟域亚稳；
**单点毛刺 ≠ 偶发塌陷**，两者根因不同
③ 同步器位置选择：**尽可能靠近被同步模块的输出**（不要散在多个下游里各打各的），
保持信号流一致性
④ 多 bit 数据跨同频异相域也用 2 拍寄存器（不要用 FIFO/格雷码——10ns 相位差 bit skew 可控）

### L30. "差值型"测量出问题 → 把差值拆回原始分量分别观测，一击定位到具体位（2026-09-10）

**现象**：vpp 长期在两簇间跳（447~455 / 478~485，**Δ≈32**），VOFA 折线图大量上下尖刺；而 period/bin 完全正常。

**定位过程（排除法 + 拆分观测）**：
1. **ADC_IN 接地** → 排除输入路径（信号源/线缆/调理）
2. **内部 DDS→DAC** → 排除 FPGA→DAC 通路
3. **`W1`+`A0`（DAC 输出静止、数据线不翻转）** → 排除 DAC 串扰
4. **把 vpp_measure 的窗口 max/min 各自还原成原始码，分别上报**（格式改 `<max码>,<period>,<bin>,<min码>`）
5. 结果：**max 稳定 621~623，min 分两簇 136~142 / 168~185**
   → `168 − 136 = 32` = **bit5 的权重**
   → `136=0b0010001000` 与 `168=0b0010101000` 差的正是 bit5
6. 而 bit5 = `ad_data[5]` = **唯一走手工飞线的位**（原脚 R19 被 CPU 占用，改飞 P17）

**结论**：手工飞线的位线信号完整性差（边沿迟滞/串扰）→ ADC 输出翻转时该位来不及建立 → 采样采到旧值 → **该位间歇性翻转**。
（幅度小时 32 LSB 占比更大，所以"小信号更容易看到"）

> ⚠️ **2026-09-10 下午修正（保留原判断过程）**：用户按"双绞 + 焊死"重焊后，**±32 双簇依旧存在**
> → **"接触不良"这一支被证伪**（[已排除]）。
> 但 **"翻的是 bit5"仍然成立**（MASK_BIT5 实验已证）→ **机制应归为"串扰 / 采样裕量"，不是接触**。
> 另外回看数据发现：**`W1`+`A0`（DAC 输出静止）时双簇消失** → **DAC 的翻转参与了形成**（容性串扰嫌疑最大）。
> ⭐ **重要认识**：**双绞对"磁性耦合（环路）"有效，对"容性耦合（相邻走线电场）"几乎没有屏蔽作用**——
> 抗容性串扰需**屏蔽层（细同轴/铜箔）**或**物理拉开距离/让地线隔在中间**。

**方法论（可复用）**：
- ⭐ **"差值型"测量（max−min、ΔT、差分电压）出问题时，第一步是把差值拆回原始分量分别观测** —— 差值会把"哪一端被污染"这个关键信息掩盖掉

- 飞线补救顺序：缩短 → 伴地线 → 源端串 33Ω 阻尼；理想是换用有正规走线的空闲 IO

### L31. 不要用 PLL 输出做"全设计系统时钟"（Gowin）——综合通过、板子全死（2026-09-10）

**现象**：为消除 CDC，把所有逻辑的时钟从板载 `clk50` 换成 PLL 输出 `pll_clk1`。
综合/布线**零 error**，烧录后**整块板子不工作**（连 UART 都没输出）。

**机理**：
1. 逻辑搬走后 `clk50` 只驱动 mdclk 计数器 → 被工具**降级到通用布线**（`WARN PR1014`）
2. `clk50` 同时是 **PLL 输入** 与 **PLL_INIT 的 mdclk 来源**
3. `pll_init.v` 的初始化 FSM 必须等 `I_LOCK` 才释放 PLL 复位
4. 资源报告的 "Global Clock Signals" 里**看不到 PLL 输出作为主时钟**
⇒ PLL 未被释放 → 全设计无时钟 → 死

**教训（可迁移到任何"把系统时钟换成 PLL 输出"的场合）**：
- ⭐ **系统时钟留在板载输入时钟域**，PLL 只用来产生**相移的专用时钟**（给外设/ADC 采样）。
  这样即使 PLL 出问题，**UART/心跳仍活着 → 故障可观测**。
- 需要"单时钟域 + 相移采样"时，**把相移加在"给外设的时钟输出"上**，逻辑仍跑板载时钟。
- ⭐ **"综合无 error"≠"能跑"**：高云这类问题**只以 WARN 出现**，必须主动看构建报告。

**必看的三个构建报告位置**：
| 文件 | 找什么 |
|---|---|
| `impl/pnr/*.log` | `WARN PR1014`（时钟被降级到 generic routing） |
| `impl/pnr/*.rpt.txt` | "Global Clock Signals" 表（主时钟在不在上面） |
| `impl/gwsynthesis/*.log` | PLL 相关模块是否真的被编译进去 |

**关联**：手册 #23；TROUBLESHOOTING 阶段 26。

### L32. 高速输出与敏感输入落在同一 IOB tile / 相邻 ball → 该输入位间歇翻转（2026-09-10）

1. 器件引脚库（Gowin）：`C:\Gowin\<版本>\IDE\data\device\<器件>\PBGA484A.json`
   字段 `PIN_DATA[].INDEX`（ball 名，如 `P17`）→ `NAME`（IOB tile，如 `IOB140B`）/ `PAIR` / `BANK`
2. 工程 P&R 报告 `impl/pnr/*.rpt.txt` 的引脚表：`端口名 | ball/脚号 | Site`

### L33. "局部性检验"：用"冻相邻 vs 冻远端"区分近场耦合与分布式耦合（2026-09-10）

**要解决的问题**：某个输入位被干扰，但**干扰发生在 FPGA 侧（引脚邻域）还是外设/模块侧**？
两者现象一模一样，必须靠**局部性**分开。

**方法**：给干扰源（这里是 10 位 DAC 数据总线）加一个**逐位使能掩码**（冻结某些位使其不再翻转），
然后对比：

| 冻结对象 | 若耦合是"近场（FPGA/PCB 邻域）" | 若耦合是"分布式（模块内/共阻抗）" |
|---|---|---|
| **与受害位相邻的干扰源** | 改善**很大** | 改善 ≈ 该位占比（如 1/10） |
| **远离受害位的干扰源** | **几乎无改善** | 改善 ≈ 1/10（与上面相当） |

→ **判据：相邻位的改善幅度是否显著大于远端位。** 显著 → 近场；相当 → 分布式。

**关键设计要点**：
- **必须做成"可用参数/运行时可改"**（本次用 `parameter DA_FREEZE_MASK`，若不反复综合更好）
- **量化指标要选"计数型"而不是"极值型"**：极值（vpp max/min）只由个别样本决定，噪声大；
  本次新增 `glitch_count`（相邻样本跳变超阈值的点数）作为统计量，A/B 对比信噪比高得多
- 阈值要与**真实信号斜率**留出余量（正弦相邻样本最大变化 = A·2πf/Fs；100kHz→6.3LSB、200kHz→12.6LSB，取 THR=16）

**通用性**：凡"某个输入通道被干扰、想判定干扰来自本板还是外部设备"的场合都可套用。

**关联**：L32；TROUBLESHOOTING 阶段 34/35；`src/glitch_count.v`

### L34. 诊断手段不能改变被测对象——"屏蔽某一位"会自造该位的跳变（2026-09-10）

**背景**：为了定位"10 位 ADC 数据里哪一位不稳"，我做了 `ADC_MASK_AUTO`：自动循环 11 档，
分别"屏蔽 bit0 … bit9"，看毛刺计数是否回落。**实验跑通了、数据也干净，但结论无效。**

**为什么无效**：屏蔽一位 = **改变了被测信号本身**。
```
设被屏蔽位权重 w = 2^N。屏蔽后，每当真值跨越 2^N 的奇数倍边界：
   真值 31 → 32   屏蔽 bit5 后：  31 → 0     跳变 31
   真值 63 → 64   屏蔽 bit6 后：  63 → 32    跳变 31
   真值 127→128   屏蔽 bit7 后：  127→ 64    跳变 63
⇒ 每个边界自造 ~(2^N − 1) LSB 的人工跳变
```
**实测指纹**（`gmax` 峰值）：屏蔽 b5→**37**、b6→**69**、b7→**133**、b8/b9→**255(饱和)**
≈ 2^N + 信号斜率(≈6)。**完全对得上 ⇒ 指标被自造跳变污染。**

**推论（判据）**：只有当 **2^N − 1 < 判定阈值** 时该档才干净。
本次阈值 16 ⇒ **只有 b0~b3 有效**；b4 起作废。
> 这次能看出污染，靠的是"**先把 gmax 的分布打印出来看形态**"——如果只比较均值，
> 会误以为"屏蔽 b5/b6 让毛刺变多"是真实效应。

**既得的意外收获**：干净档位（b0~b3）显示**没有任何单一位是元凶**；
而 `gmax` 分布全部落在位权重上 → 见 **L35**。

**更该用的替代手段**（不改数据）：
- 统计量换成**"位翻转事件数"**（只数"该位在两拍之间翻转"的次数 + 与邻居位比较），而不是数值差
- 或直接用 **L30 的"差值拆原始分量"**：把 max/min 分开上报，看是哪一端被污染（本次已用此法定位到 bit5）

**一句话**：**任何"为了看清它而修改它"的诊断，都要先问一句"我改的是不是被测对象本身"。**

**关联**：L30（差值拆分量）、L35；TROUBLESHOOTING 阶段 44；`top_system.v` 的 `ADC_MASK_AUTO`

### L35. 跳变幅度的"整齐程度"能区分"位翻转型"与"模拟噪声型"故障（2026-09-10）

**现象**：毛刺的**单次最大跳变幅度 `gmax`** 分布高度集中在几个离散值上：

| gmax | 占比 | 解读 |
|---|---|---|
| **32 / 33** | **48%** | bit5（33 = 32+1） |
| **17** | 16% | bit4 + bit0（16+1） |
| 28 / 30 / 31 / 26 | ~15% | 32 − (4/2/1/6) |
| 255（饱和） | 13% | 多位同错 |

**判据**：
```
跳变幅 = 整数个"位权重"（1/2/4/8/…/512）
   ⇒ 采样瞬间数据线的各位没同时稳定（位偏斜 / 建立裕量不足 / 引脚串扰）
   ⇒ 排查方向：采样相位、时序约束、引脚分配、数据线长度与回流

跳变幅是连续分布（什么样的值都有）
   ⇒ 模拟侧噪声 / 电源地弹（SSN）/ 基准不稳
   ⇒ 排查方向：去耦、地回路、模拟前端
```
**旁证（自洽性检查，很有用）**：基线里 16% 的窗口 `gmax = 17`（= bit4+bit0）。
屏蔽 bit0 后跳变变成 16，而判定是 **`diff > THR`（严格大于，THR=16）**
→ 16 不再计数 → 三处同时变化：glitch 4.66→2.61、`glitch=0` 占比 4.0%→**21.6%**、
`gmax=16±3` 占比 15.7%→**0.4%**。**三条独立指标同向自洽 ⇒ 机制解读正确。**
> 这种"改一个变量，看多个指标是否**同时**朝预期方向动"的自洽性检验，
> 比单一指标的改善更有说服力。

**关联**：L29（max-min 对单点敏感）、L34；TROUBLESHOOTING 阶段 44

### L36. 循环缓冲的写指针必须显式复位（2026-09-10）

**现象**：新写的 `raw_dump.v`（1024 点循环缓冲 + 冻结回传）仿真时**读出的 1024 个样本全是 X**，
但 UART 帧头/帧尾、十进制格式、状态机流转**全部正常**（TB 里字节监视显示数字位是 `0xxx`）。

**根因**：
```verilog
reg [AW-1:0] wr_addr;
always @(posedge clk) begin            // ← 没有复位
    if (data_valid && !captured) begin
        mem[wr_addr] <= data_in;
        wr_addr      <= wr_addr + 1'b1;
    end
end
wire [AW-1:0] rd_start = wr_addr;      // ← 仿真中 wr_addr = X → rd_start = X
                                       //   → rd_addr = X → mem[X] = X
```
- **仿真中**：未初始化寄存器 = X，地址为 X → 读出 X。**上板也许"恰好能跑"**（器件上电后多为 0），
  所以这类 bug 只在仿真里暴露，反而说明**仿真环境更严格**。
- 与 **L19**（TB 里 reg 未初始化导致断言被跳过）同源，但发生在 **RTL 内部状态**上，更隐蔽。

**教训**：
1. **凡"指针/累加器/状态机"这类内部状态，一律给显式复位**——不要依赖上电初值。
2. 症状识别：**"控制流全对、数据全 X"** → 优先怀疑"地址/指针为 X"，而不是数据源或时序。
3. 回传/导出类功能很适合用"位流导出 + 离线解码"验证（本次即如此），因为能看到"帧对了但内容是 X"
   这种分裂现象——比只看"有没有输出"定位快得多。

**关联**：L19、L37；`src/raw_dump.v`；`sim/tb_raw_dump.v`

### L37. 主 FSM 与"字节发送子 FSM"握手：别在 done 同拍重启（2026-09-10）

**现象**：`raw_dump.v` 的帧头本应是 `#RAW\n`（5 字节），实测**多出一个 `#`**（变成 `##RAW\n`）。

**根因**（典型的两级状态机竞态）：
```verilog
B_IDLE: if (byte_req) begin tx_data_r <= byte_val; ... end        // ← 问题在这
B_WDONE: if (tx_done) begin byte_done <= 1'b1; bst <= B_IDLE; end
```
- 子 FSM 在 `B_WDONE` 置 `byte_done=1` 并回到 `B_IDLE`；
- **同一个时钟边沿**，主 FSM 也看到了 `byte_done` 并更新自己的下标（如 `mark_idx++`）；
- 于是下一拍子 FSM 已经又在 `B_IDLE` 且 `byte_req` 仍为高 → **立刻再发一字节**，
  而此刻主 FSM 的 `byte_val` 组合逻辑仍按**旧下标**取值（NBA 右侧用边沿前的值）→ **重发旧字节**。

**修法**：子 FSM 的起动条件加一条 `!byte_done`
```verilog
B_IDLE: if (byte_req && !byte_done) begin ... end
```
代价是每字节多 1 拍间隙（对文本回传完全可接受），换来握手无歧义。

**通用规律**：**"电平请求 + 单拍完成"** 这类握手，只要"请求"是由**组合逻辑从另一个状态机的寄存器**
导出的，就必须保证"完成当拍不重启"，否则必然出现"用旧数据重发一次"。

**验证方式**：在 TB 里**直接监视最末端 DUT 的装载信号**（本次监视 `tx_start_r` 那一刻的 `tx_data_r`），
比事后解码位流更容易定位"多发了一个字节"。

**关联**：L36；`src/raw_dump.v`

### L38. 采样点必须落在"数据出现 + 建立时间"之后（2026-09-10）

**背景**：源同步接口（ADC 输出 + FPGA 捕获）的采样相位，常见做法是"放在数据稳定窗中心"。
但**稳定窗的起点是"数据出现时刻 + 建立时间"**，而建立时间在**多位同时翻转**时会显著变长。

**本次实测（3PA1030 + GW5AT，25MHz）**：
```
数据在 ad_clk 沿 +25ns 出现；采集时钟相位 270° = +30ns → 只等了 5ns
→ 中码 511↔512 需要 **10 位同时翻转** → 输出建立 >5ns → 采在跳变过程里
→ 锁存"新旧位逐位混合"的码（实测偏差 −341/-374/+67 LSB）
```

**识别特征（三条，缺一不可互相印证）**：
1. 坏点**只**出现在"多位同时翻转"的码边界（如中码、2^k 边界），**不在**任意位置随机出现
2. 偏差幅度 **∝ 同时翻转位数**（10 位 ≈ ±340；4~6 位 ≈ ±20；2~3 位 ≈ ±10~16）
3. 坏值是**逐位混合的整齐值**（如 `170 = 0b10101010`），不是连续分布的模拟噪声
4. 方向与穿越方向相关（MSB 最后稳定：上升穿越 → 偏低；下降穿越 → 偏高）

**与"耦合/接触不良"的区分**：以上 4 条只要成立，就不是耦合、不是接触不良 ——
所以**重焊、双绞、加电容、屏蔽、换引脚、冻结干扰源全都会无效**（本次全部验证过）。

**修法**：把采样相位挪到"距上次数据出现尽量远、距下次出现留够 hold"的位置。
本次从 270°（+30ns，距数据出现仅 5ns）→ **135°（+15ns，距上次出现 30ns、距下次 10ns）**，
建立裕量 5ns → 30ns。

**通用公式**（周期 T、数据出现延迟 tOD、建立时间 d）：
```
安全相位区间（mod T）= [tOD + d, T + tOD − t_su]
取区间中点最稳
```

**关联**：L39；TROUBLESHOOTING 46 号；`src/adc_capture.v` 文件头

### L39. 算时序裕量必须用"实测频率"，不能用标称值（2026-09-10）

**现象**：此前按"ADC 时钟 50MHz"推导采样相位，得出"270° 位于稳定窗中心、裕量 10ns、是最优点"。
实际根因恰恰是**270° 最差**。

**真因**：`gowin_pll.ipc` 里 `ClkinClockFrequency=100`（向导填的），而板载 `sys_clk` 实际 **50MHz**
→ 所有输出频率**静默减半**：给 ADC 的时钟只有 **25MHz**，周期 40ns 而非 20ns。
→ 数据出现时刻、相位对应的绝对时间全部变了 → 裕量从"10ns"变成"5ns"，且 270° 从最优点变成最差点。

**怎样在"没有示波器/频率计"的情况下发现**：
- 抓一段**原始采样序列**，看**样本是否成对/成组重复**
- 本次：`v[2k]==v[2k+1]` 占 **99.8%**（另一帧 `v[2k+1]==v[2k+2]` 占 100%），
  且**相同值游程长度全为偶数**（2/4/6/8/10…）→ 数据每 2 个系统时钟才更新一次
  → **采集时钟 = 缓冲区写速率的一半 = 25MHz**
- 对照：频率计读数正确（100kHz → period=500，说明 clk50 确实是 50MHz）→ 排除"系统时钟也不对"

**教训**：
1. IP 向导里的**输入频率**必须和板载实际一致；填错**不报任何错**，只让输出频率整体偏移（静默失效）
2. 注释/文档里的时钟频率**不能用来算裕量**——必须实测或从数据特征反推
3. 代码注释与 IP 配置"漂移"过一次（180° vs 270°），这次是"频率漂移"——**同类风险的第二次**

**关联**：L38；L31（不要用 PLL 输出做系统时钟）；工具经验 U23（配置类事实查源文件）

### L41. "源样本被重复 N 次"会击穿一切极值型统计（2026-09-10）

**背景**：为了抗"偶发单点坏值"，常见做法是把 `max−min` 改成"第二大 − 第二小"。
**但如果数据流里每个源样本被重复了 N 次（采样率只有缓冲/处理速率的 1/N），这个办法直接失效** ——
一个坏源样本会在缓冲里出现 N 次，占掉前 N 个极值名次。

**实测（1024 点原始帧，采样率 = 缓冲速率的一半 → N=2）**

| 帧 | `vpp`(max1−min1) | `vpp2`(max2−min2) | `vpp3` | **5 点中值滤波后 max−min** | 真实值 |
|---|---|---|---|---|---|
| 1Vpp | 398 | **398**（零改善） | 398 | **116** | ≈107 |
| 2Vpp | 485 | **484** | 450（仍被次坏值 172 污染） | **214** | ≈215 |

- 1Vpp 帧里坏值 `170` 出现 **4 次**（帧内有**两个**坏事件，各被重复一次）→ 前 4 小全是 170，
  **连"第三大/第三小"都救不了**。
- ⇒ 极值名次法在"重复采样"下的失效条件：**K ≤ N ×（坏事件的个数）**。

**正确兜底**：
1. **先做中值/分位数滤波，再取 max−min**（本次 5 点中值 → 116/214，与真实值吻合）；
   窗长要满足 `点数 ≤ 最短信号周期 / 10`，否则会削平极值。
2. 或直接用**分位数**（如 0.5% / 99.5%）代替极值。
3. ⚠️ 但这些都是"读数补丁"，**不改数据本身**——根因（采样节拍/建立裕量）该修还是要修。

**通用检查**：拿到一帧数据，**先统计"相同值游程长度分布"**。
若长度**全为偶数**（2/4/6/8…）或重复率 >90%，就说明存在 N 倍重复，
**此时任何"取第 K 大/小"的算法都要重新评估**。

**关联**：L40（原始序列优先）；L42；TROUBLESHOOTING 49 号；工具经验 U28

### L42. 帧头/帧尾的边界样本必须单独检查（2026-09-10）

**现象**：循环缓冲"冻结 + 回放"型调试通道（本例 `raw_dump`），回传帧的
`index 0` 与 `index 1023` **数值相同**、且 `index 0` 与 `index 1` **不成对**（破坏了整体的成对重复规律）。

**机制**：触发那一拍"冻结标志"还没生效 → **仍然写了一次**，
覆盖掉当前 `wr_addr` 槽 —— 而这正是"最旧样本"所在槽，也是读指针的起点。
```
index 0   = 触发拍刚写入的样本（其实是"最新"，位置错）
index 1   = 孤儿（其重复伙伴被覆盖）
index 2.. = 连续旧→新（正常）
```
`v[0] == v[1023]` 因此可解释：二者真实时间只差 2 个源样本，慢信号下取值相同。

**修法**：写条件同时屏蔽触发脉冲 —— `if (data_valid && !captured && !dump_req)`。

**判据（分析前先跑一眼）**：
- `v[0] == v[-1]` 且 `v[0] != v[1]` → 帧首有错位样本
- 影响面：**中间数据不受影响**，但会污染"边界统计"和"成对性/重复率"这类整体判断
  （本例正是它让"成对重复率"从 100% 掉到 99.8%，差点掩盖真正的重复规律）

**关联**：L41；工具经验 U28；`ADDA/src/raw_dump.v`

### L43. 「TB 通过」≠「修复被验证」（2026-09-10）

**事件**：把 `raw_dump` 的写条件从 `!captured` 改成 `!captured && !dump_req`，声称
"TB 复跑 16/16 全对"。**这个通过证明不了任何事** —— 外部评审指出后核查属实：

```verilog
    for (i = 0; i < 24; i = i + 1) begin ... data_valid = 1'b1; end
    @(negedge clk);
    data_valid = 1'b0;              // ← 触发之前就拉低了
    repeat (4) @(negedge clk);
    dump_req = 1'b1;                // ← 此时 data_valid=0 → 那一拍根本不会写
```

被修的 bug 是"**触发那一拍仍然写了一次**，覆盖了最旧样本槽"。而旧 TB 在触发前就把
`data_valid` 拉低了 → **那一拍本来就不写** → 竞争条件不可能出现 → **旧代码也照样通过**。

**正确做法（本次照此重做，已验证）**：
1. **让 TB 覆盖实机条件**：`data_valid` **全程为 1**（实机 `adc_valid` 恒为 1），
   数据用"每拍 +1 的斜坡"（任何错位/重复都破坏单调性，一眼可辨）
2. **让 TB 自检**：把发出的数字重新拼成样本值，检查"严格 +1 递增"
3. ★ **拿"修复前 / 修复后"两版代码各跑一遍**，确认 TB 能分辨：
   | 版本 | 帧 | 判定 |
   |---|---|---|
   | 修复后 | `[10,11,12,…,25]` | `[PASS] 帧内严格 +1 递增，无错位样本` |
   | 旧代码 | `[26,11,12,…,25]`（**帧首 = 帧尾+1**） | `[FAIL] 旧 bug 仍在` |

**通用规律**：
- **一个测试的价值 = 它能否在"错误版本"上失败。** 只在正确版本上跑通，等于没测。
- 写 TB 前先问：**这个 bug 需要什么条件才会发生？我的激励给了吗？**
  （本例：需要"写入与冻结在同一拍竞争"）
- 边界/竞争类 bug 尤其容易"恰好避开"——激励必须**贴着条件构造**。

**关联**：TROUBLESHOOTING 49/50 号；L42（帧边界样本）；工具经验 U28

### L44. 相位类问题：不要用"标称参数 + 零延时"推最优相位 —— 用"差/差/好"三点反推真实环路延时（2026-09-10）

**背景**：ADC 采样相位 270° 时坏值 3.7%，改成 **135° 后 0%**，而 0° 时也很差。

**方法（可复用到任何"采样点 vs 数据跳变"问题）**
```
设 数据跳变时刻 = D (mod T)；采样相位 = ψ；裕量 = 圆上距离(ψ, D)
  270°(ψ=30) 差 → D ∈ [25,35]
    0°(ψ= 0) 差 → D ∈ [35,40] ∪ [0,5]
  ⇒ 唯一解 D ≈ 35ns
     （datasheet 只给 tOD = 25ns，多出的 ~10ns =
       慢沿时钟输出 + 排线/转接板 + FPGA 输入路径）
  ⇒ ψ = 135°(15) 距 D 为 20ns（两侧各 20ns）= 理论最优
     45°(5) 只有 10ns；225°(25) 只有 10ns；315°(35) 为 0ns（最差）
```

**三条经验**
1. **未知延时 D 一项就能把结论翻面**：若假设 D=0，算出"眼中心 45° 最优"；实际最优是 135°。
2. **裕量必须按"圆上距离"（mod T）算**，不是线性相减：T 内只有一个危险点，最优点在它对面 T/2 处。
3. **一次相位扫描的本质就是测 D**：扫到"最差档"的位置 ⇒ ψ ≈ D，据此可直接定最优相位，不必找"平台"。

### L46. 阈值型判据必须留"死区"（迟滞）—— 否则噪声会造出假边沿（2026-09-10）

**现象**：过零/过阈计数**偶发**偏高。上板实测（100kHz/2Vpp）：`period` 读到 **437 / 468**（真值 500），
折合频率 **+14.4% / +6.8%**；而**同一批 4 帧里有 2 帧完全正确** → 短窗口/单帧看永远发现不了。

**机理**：`rise_edge = (d1 < TH) && (data_in >= TH)` 这种"单点阈值"判据，
当信号**朝远离阈值的方向**穿越时，噪声只要把某一拍推回阈值另一侧，就会多算一个边沿。
（本例：下降穿越 512 时，噪声把某拍推回 ≥512 → 假上穿。）

**定量（数值规律就是证据）**
```
设窗口里混进 N 个假边沿 → 16 个间隔只覆盖 (16−N) 个真周期
  avg = (16 − N) × P / 16
  N=1 → 468.75（实测 468 ✓）    N=2 → 437.5（实测 437 ✓）
⇒ 一看到 468/437，就能排除"时钟不稳/信号源不稳"，直接锁定"多算了 1~2 个边沿"
```

**修法**：加迟滞带 H —— 上穿需 `>TH+H`、下穿需 `<TH−H`，并用**状态寄存器**（不是"上一拍"）记忆当前在哪个带。
代价：幅度小于 2H 的信号不再产生边沿 → **H 必须按"最小可用信号幅度"反推**（本例 H=4 → 幅度需 >8 LSB）。

**通用**：任何"过阈值就触发"的判据，先问一句 **"阈值附近抖动会怎样"** ——
过零检测 / 按键消抖 / 比较器回差 / 控制环开关点 / 软件里浮点相等比较 / 重试与告警门限。

**关联**：TROUBLESHOOTING 54 号；共性集 C12；工具经验 U31

### L47. 单点极值有系统性偏置 —— 峰值要用"带内均值"而不是"最高那一拍"（2026-09-10）

**现象**：`max−min` 做峰峰值估计，读数**系统性偏高**：上板实测 2Vpp（示波器基准 2.00Vpp）读 215 LSB，
而正弦拟合真值只有 210 LSB → **+5 LSB（+5.08%）**，而判据容差是 ±(5mV+5%) = ±105mV → **只剩 3mV 余量**。

**为什么必然偏高**：窗口内 N 个样本各带噪声，`E[max] ≈ A + 3.1σ`、`E[min] ≈ −A − 3.1σ`
⇒ **`E[max−min] ≈ 真值 + 6σ`**（σ=1.4 → +8 LSB 量级）。
关键：这是**绝对量**，与信号幅度无关 ⇒ **幅度越小相对误差越大**
（1Vpp：+5 LSB = +5%；300mVpp：+5 LSB = +17%）→ 小幅度档直接超差。

**修法（两遍窗口 + 一次除法，无需排序、无需 DSP）**
```
第1遍：统计 max/min → pp1 = max−min；带宽 BAND = max(pp1>>6, 4)
第2遍：v ≥ max−BAND 的样本 → sum_hi/cnt_hi ；v ≤ min+BAND 的样本 → sum_lo/cnt_lo
输出：vpp = mean_hi − mean_lo + 2·BAND/3
```
- **`+BAND/3` 的来历**：峰附近近似抛物线（正弦 `x = A − Aθ²/2`），
  **带内均值 ≈ 峰值 − δ/3** ⇒ 加回 δ/3。三角波近峰是直线（均值 = 峰值 − δ/2，残余 −δ/6）；
  方波带内全是峰值样本（均值 = 峰值，残余 +δ/3）→ 三种波形残余都在 ±1~2 LSB。
- **带宽要"自适应 + 绝对下限"**：`BAND = max(pp>>6, 4)`。太窄 → 带内样本数会掉到 0
  （两遍窗口的相位对齐一变就发生，实测 vpp 偶发 0）；下限 4 LSB 保证样本数与抗噪。
- **样本数不够要回退**：`cnt < 4` 时退回 `max−min`（宁可偏一点，不要出 0）。

**效果**（同批数据、三种波形 × 三个幅度）：误差从 **+3~+5 LSB 降到 0~±1 LSB**。

**通用**：任何"用极值估计幅值"的地方都有这个偏置 —— 峰值检波、包络检测、
      软件里的 `max()`/`min()` 统计、性能测试取最大值（max 永远受离群点支配）。
      **要抗噪就得"对峰值附近的一批样本取平均"，而不是只取那一个。**

**关联**：TROUBLESHOOTING 55 号；L48（TB 必须持续喂数据）；`src/vpp_measure_band.v`

### L48. 测窗口的 TB 必须"持续喂数据"（2026-09-10）

**踩坑**：新 TB 里喂完 `N` 拍就停止驱动 → **最后一个窗口的数据冻结** →
`max == min` → 读数 0 → 看起来像"RTL 坏了"，白查半天。
探针打印 `cur_max=104 cur_min=104`（两者相等）才看穿是激励问题。

**规矩**：
1. **被测窗口必须持续喂数据**：统计量要在"喂数据期间"累加，停喂后产生的窗口一律作废。
2. 判"读数不对"之前，先**探针内部寄存器**（`dut.cur_max` 这类层次引用），
   区分"激励没到"和"逻辑算错"——这一条能省掉一半的假故障。
3. 与 L43（TB 通过 ≠ 修复被验证）配套：**TB 既不能"恰好避开 bug"，也不能"自造故障"**。

**关联**：L43；TROUBLESHOOTING 55 号
