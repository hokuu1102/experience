## 二、更新约定（每次排查完问题后执行）

1. **过程** → `TROUBLESHOOTING.md`：现象 / 假设 / 验证 / **失败尝试** / 根因 / 回归结果，
   编号接排，顶部索引补行。**失败路径本身就是经验**，必须写。
2. **可复用结论** → 按类型分流：
   - 代码逻辑 / 时序 / 设计思路 → 逻辑集 `L##`
   - 工具 / 软件 / 操作流程 → 工具集 `U##`
   - 环境 / 编译报错 → `FPGA问题排查手册.md`
   - 能跨语言、跨领域迁移的 → 共性集 `C##`
3. **状态标签**（统一）：`[假设]` / `[验证中]` / `[已基本确认]` / `[已确认]` / `[已排除]`。
   **只有验证过的才能写进"最终方案"。**
4. **推翻旧结论必须当场改旧记录**（保留"错误 → 修正"痕迹，不删历史）。
5. **条目之间用编号互指**（如"见 L44 / U29 / C11"），不要复制粘贴正文。
6. **生成物与个人记录不入库**（见 `.gitignore`）：
   - 生成物 / 缓存：`*.fst / *.vvp / *.vcd / logs/ / __pycache__`
   - ⛔ **采购 / 备料 / 台账**（`备料.md`、`*.xlsx`）：含**立创订单号、单价金额**，
     还会暴露其它项目的存在与 BOM 状态 —— **本库可公开，这类不进来**。
7. ⭐ **本库只记"器件级通用知识"**（参数 / 坑 / 选型判据 / 同类对比）。
   **具体项目的选型落地与决策记录，写在各项目自己的仓库**，不写进本库。
   ⚠️ 具体表现：不要写"本项目选定 XX""我方采用 XX"，改写成
   "这种场景该选 XX"。**保留知识，去掉项目身份。**
8. ⚠️ **初始化新仓库时：先写 `.gitignore` 再 `git add`**，不要一把梭 `add -A`。
   （本库吃过一次亏：`备料.md` 与台账在初始提交时被一起提交并推到公开远端，
   事后只能 `git rm --cached` 摘出，**历史里仍然留着**。）
